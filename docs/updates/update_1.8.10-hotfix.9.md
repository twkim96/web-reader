# Web Reader 1.8.10 hotfix.9 — 도서별 독립 회차·리더 메뉴 끝선 보정

작성일: 2026-08-13

기준 커밋: `85629ca`

상위 문서: [update_1.8.10.md](./update_1.8.10.md)

상태: 구현·전체 자동 gate 완료. 실기기 확인 대기

## 실사용 finding

- 통계 상단이 서로 다른 책의 기록 행 수를 `N회차`라고 합쳐 표시하고, 각 책의 첫 행에서는 `1회차`를 숨겨 회차가 전역 순번처럼 보였다.
- iPad 가로 화면에서 리더 메뉴 오른쪽 끝이 실제 글자 끝선보다 바깥에 있었다. Foliate의 외부 여백만 계산하고 iframe 안쪽의 본문 여백을 포함하지 않은 것이 원인이었다.

## 변경

### 도서별 독립 회차

- 회차 계산은 기존처럼 `bookId`별로 독립 유지한다.
- 각 도서의 첫 독서는 `1회차`로 표시한다.
- 한 책을 완독한 뒤 처음부터 다시 읽을 때만 같은 책에 `2회차` 행을 추가한다.
- 재독 회차의 시간·시작일·완료일은 다른 회차와 합치지 않는다.
- 전체 회차 수는 표시하지 않고, 각 책의 최신 회차를 기준으로 `N권 읽는 중 · 완료 N권`만 표시한다.
- IndexedDB·Firestore schema와 독서 session 동기화 payload는 변경하지 않는다.

### 리더 메뉴 글자 끝선

- Foliate `gap: 5%`가 만드는 외부 절반과 iframe 내부 절반을 모두 반영한다.
- 본문이 viewport 안에서 펼쳐지면 메뉴 오른쪽 끝을 실제 글자 끝인 viewport 5%에 맞춘다.
- 단일 페이지가 1000px 최대 폭에 걸리면 중앙 외곽 여백에 약 26.3px의 내부 글자 여백을 더한다.
- 2페이지 모드는 2000px 최대 펼침 폭을 기준으로 같은 계산을 적용한다.
- 고정 레이아웃은 본문 글자 끝선이 없으므로 기존 안전영역+16px을 유지한다.
- 서비스 워커 script를 갱신해 설치형 PWA도 변경을 감지한다.

## 자동검증

- 서로 다른 세 권의 첫 기록이 모두 `1회차`인지 확인한다.
- 한 책의 완독 후 재독만 `1회차`, `2회차`로 분리되는지 확인한다.
- production browser에서 모든 행에 회차가 표시되고 상단 요약에 전체 회차 수가 없는지 확인한다.
- 320px 모바일, 1280px 단일 페이지, 1366px 2페이지에서 메뉴 오른쪽 끝이 실제 글자 끝선과 일치하는지 확인한다.

## 실기기 확인

- 여러 소설을 한 번씩 읽었을 때 각 행이 모두 `1회차`이고 상단에는 `N권 읽는 중 · 완료 N권`만 보이는지 확인한다.
- 한 소설을 완료한 뒤 처음부터 다시 읽으면 같은 제목의 `1회차` 완료 행과 `2회차` 현재 행이 함께 보이는지 확인한다.
- `2회차` 시간이 0부터 새로 증가하고 `전체 | 현재 | 완료` 필터가 각 행을 올바르게 나누는지 확인한다.
- iPad 가로 1페이지·2페이지 모드에서 메뉴 오른쪽 끝이 오른쪽 페이지의 글자 끝선과 일치하는지 확인한다.
