# Web Reader 1.8.10 hotfix.7 — 모바일 모달·독서 시간·회차 통계 정리

작성일: 2026-08-12

추가 수정: 2026-08-13

기준 커밋: `d5c46bf`

상위 문서: [update_1.8.10.md](./update_1.8.10.md)

상태: 구현·전체 자동 gate 완료. 모바일·iPad·PC 실기기 확인 대기

## 실사용 finding

라이브러리 전체 주석 창은 모바일에서 높이 `92dvh`, 폭은 거의 화면 전체를 사용하고 PC에서는 최대 `5xl`까지 넓어졌다. 통계 창을 축소한 뒤에도 이 창만 화면을 과도하게 차지하고, 주석 관리에 필요한 정보량보다 외곽과 내부 여백이 컸다.

## 변경

### 라이브러리 주석 모달

- 통계 모달과 동일하게 모바일 최대 높이 `78dvh`, 넓은 화면 `82dvh`를 사용한다.
- 폭은 `min(90vw, 36rem)`으로 제한한다.
- 주석이 많아도 모달 외곽은 커지지 않고 결과 목록만 세로 스크롤한다.
- 헤더, 검색·필터, 내보내기 영역의 세로 여백을 줄인다.
- 주석 행의 위아래 padding을 줄이고 긴 내용이 본문 폭을 늘리지 않도록 가로 overflow를 차단한다.
- 닫기 버튼은 44×44px touch target을 유지한다.
- 검색, 도서·색상·메모·정렬 필터, 내보내기, 공유, 주석 이동 동작은 변경하지 않는다.
- 서비스 워커 script를 갱신해 설치형 PWA도 변경을 감지한다.

### 리더의 현재 도서 누적 시간

- 모바일·태블릿·PC 모두 중앙 하단 정보줄을 `목차 · 진행률 · 위치 이동(#) · 누적 시간` 순서로 표시한다.
- `진행률 → #`와 `# → 누적 시간`은 같은 간격을 사용한다.
- `00:00` 형식의 시간은 중앙 정보와 같은 글자 크기·세로 기준선을 사용하고, 서체는 책갈피·주석 목록의 인용문과 동일한 `font-serif` 명조 계열로 흐리게 표시한다.
- 시간은 IndexedDB에 확정된 현재 owner의 로컬·원격 수신 기록과 아직 확정되지 않은 현재 기기의 활성 구간을 합산한다.
- 서버를 새로 조회하거나 독서 기록을 추가 저장하지 않는다.
- IndexedDB 변경 알림이 있을 때만 확정 기록을 다시 집계하고, 활성 구간은 메모리에서 5초마다 확인하되 분 값이 바뀔 때만 React 상태를 갱신한다.
- 화면 독서와 TTS 시간을 함께 합산하며 기존 기기 간 겹침 제거 통계는 그대로 사용한다.

### 리더 하단 메뉴 실기기 밀도 조정

- 모바일 리더 메뉴의 아이콘·글자 크기는 기존 규격을 유지하고, 전체 가로 길이는 기존 300px과 1차 축소안 250px의 중간인 `17.1875rem`(275px)으로 조정한다.
- 모바일의 진행률·검색·하단 버튼 행은 가로 축소율과 같은 약 8.33%만큼 세로도 줄여 기존 약 50.4px에서 약 46.2px로 조정한다. 위쪽 원형 듣기·통계는 최소 44px 터치 영역을 유지한다.
- 메뉴 내부 글자 굵기는 `700 → 500`으로 두 단계 낮추고, 책갈피 숫자는 `900 → 700`으로 낮춘다.
- `md` 이상 iPad·PC에서는 폭을 `18.90625rem`(302.5px)으로 넓히고 행 높이·아이콘·글자·간격을 모바일의 약 110%로 표시한다.
- 듣기와 독서 통계는 하단 3버튼 행에서 분리해 검색창 위 우측에 `듣기 → 통계` 순서의 원형 아이콘으로 배치한다.
- 하단 행은 `책갈피 → 테마 → 설정` 순서를 유지하되 원래 메뉴의 상대 폭인 `1.35 : 1 : 1`로 남은 가로 공간을 채운다.
- 리더의 통계 버튼은 책장과 같은 통계 모달을 열며, 저장·동기화·새로고침 계약은 공유한다.
- 메뉴의 오른쪽 끝은 화면 가장자리 대신 Foliate가 실제 사용하는 본문 컨테이너의 오른쪽 끝선에 맞춘다. 모바일의 안전영역+16px을 최솟값으로 유지하면서, 본문 최대 폭 `1000px` 밖의 중앙 여백과 Foliate의 2.5% 바깥 여백 중 큰 값을 사용한다.
- 2페이지 설정이 켜진 가로모드에서는 본문 최대 폭도 2배로 계산해 펼침 영역의 바깥쪽인 오른쪽 페이지의 본문 끝선을 같은 기준으로 사용한다. 텍스트 끝선이 없는 고정 레이아웃 도서는 기존 안전영역 기준을 유지한다.

### 읽기 위치 충돌의 단방향 수렴

- 일반 위치 `set ↔ set` 충돌은 화면에 양쪽 위치를 번갈아 적용하지 않고 로컬·원격 진행률을 먼저 비교한다.
- 진행률이 더 높은 위치 하나만 승자로 확정한다. 로컬이 높으면 화면을 움직이지 않고 로컬 위치를 최신 원격 revision 위에 재전송하고, 원격이 높으면 원격 위치로 한 번만 이동한다.
- 진행률이 같고 안정 anchor가 다르면 더 높은 서버 revision인 원격값으로 정리한다.
- 원격 revision이 더 높더라도 일반 원격 위치의 진행률이 현재 화면보다 낮으면 리더를 뒤로 이동하지 않고, 현재의 높은 위치를 강제 저장해 서버도 같은 위치로 수렴시킨다.
- progress reset, 로컬 reset, bookmark·annotation 충돌과 최신 로컬 위치가 바뀐 CAS 실패는 기존 수동 안전장치를 유지한다.
- 활성 도서에서 원격 위치가 승리한 자동 충돌은 화면을 먼저 이동한 뒤 저장하는 대신, 최신 로컬 intent와 원격 head를 IndexedDB에서 먼저 원자적으로 확정하고 확정된 위치로 화면을 한 번만 이동한다.
- 이미 확정된 자동 이동 명령은 같은 충돌 transaction을 다시 finalize하지 않는다. 따라서 중간에 새 원격 snapshot이 도착해도 이전 위치로 롤백했다 재이동하지 않으며, 사용자가 다음 페이지를 넘겨야 수렴하는 상태를 남기지 않는다.

### 도서별 시작일·완료일·재독 회차

- 도서별 기록의 각 행에 해당 회차의 시작일을 항상 표시한다.
- 완독한 회차는 시간 아래의 작은 `완료` 텍스트를 누르면 시작일과 종료일이 펼쳐진다.
- 완독 뒤 시작 또는 종료 진행률이 `99.5%` 미만인 새 독서 기록이 생기면 저장 형식을 바꾸지 않고 다음 회차로 파생한다. 완독 위치에서 앱이 다시 열린 뒤 첫 기록의 시작 진행률이 100%로 남더라도 종료 진행률이 낮아지면 재독으로 인식한다. 두 번째 회차부터 제목 옆에 `2회차`, `3회차`처럼 표시한다.
- 완독 직후 99.5~100% 구간에서 생긴 후속 checkpoint는 새 회차로 오인하지 않고 직전 완독 회차에 포함한다.
- 도서별 기록 우측에는 버튼 외곽 없이 `전체 | 현재 | 완료` 필터를 둔다. 기본값은 `전체`이며 `현재`는 미완료 회차, `완료`는 완독 회차만 표시한다.
- 회차는 기존 immutable 독서 session에서 화면 표시 시 계산하므로 Firestore schema, IndexedDB schema, 동기화 payload는 변경하지 않는다.

## 자동검증

- 320×640 production Chrome에서 모달 폭이 viewport의 92% 이하인지 확인한다.
- 모달 높이가 viewport의 80% 이하인지 확인한다.
- 모달 본문과 document의 가로 overflow가 0인지 확인한다.
- 닫기 버튼이 44×44px 이상인지 확인한다.
- 검색·JSON 다운로드·Markdown 공유·fallback 다운로드·리더 이동·복귀 상태 보존 회귀를 유지한다.
- 리더 하단 시간이 `HH:MM` 형식이고 본문보다 흐린 색상인지 확인한다.
- 누적 시간이 중앙 상태줄 안에서 `진행률 → # → 시간` 순서로 표시되고 양쪽 간격, 글자 크기와 세로 중심선이 같은지 확인한다.
- 누적 시간이 책갈피 인용문과 같은 serif 계열과 보통 굵기로 계산되는지 확인한다.
- 320px viewport에서 메뉴 폭 275px, 하단 행 높이 약 46.2px, 상단 듣기·통계 아이콘 44px인지 확인한다.
- 내부 버튼 글자 굵기가 500이고 책갈피 숫자만 700인지 확인한다.
- 하단 책갈피·테마·설정 폭이 `1.35 : 1 : 1`이고 텍스트가 잘리지 않는지 확인한다.
- 1280px viewport에서 메뉴 폭 302.5px, 하단 행 약 50.8px, 상단 아이콘 약 48.4px로 모바일보다 약 10% 커지는지 확인한다.
- 320px viewport에서는 메뉴 오른쪽 여백이 기존 16px이고, 1280px viewport에서는 중앙 1000px 본문 끝선과 일치하는 140px인지 확인한다.
- 2페이지 가로모드에서는 메뉴 오른쪽 여백이 펼침 본문 컨테이너의 2.5% 바깥 여백과 일치하는지 확인한다.
- 상단 아이콘 순서가 `듣기 → 통계`, 하단 행 순서가 `책갈피 → 테마 → 설정`인지 확인한다.
- 리더 통계 아이콘으로 통계 모달을 열고 정상적으로 닫을 수 있는지 확인한다.
- 원격 revision은 높지만 진행률이 낮은 위치가 초기·후속 sync에서 리더를 뒤로 이동시키지 않는지 확인한다.
- 일반 set 충돌에서 로컬 80%·원격 70%는 로컬 재전송, 로컬 30%·원격 70%는 원격 단일 이동으로 판정되는지 확인한다.
- 완독 후 재독 fixture가 1·2회차로 분리되고 시작일, 완료 상세, `전체 | 현재 | 완료` 필터가 즉시 반영되는지 확인한다.
- 단위 테스트는 `00:00` 포맷, 완독 직후 checkpoint의 기존 회차 유지, 다음 회차 분리, 회차 정렬을 검증한다.

## 실기기 확인

- Android와 iPhone에서 주석 창이 화면을 가득 채우지 않고 목록만 자연스럽게 스크롤되는지 확인한다.
- iPad portrait·landscape와 PC에서 폭이 과도하게 넓지 않으면서 필터와 긴 원문·메모를 읽을 수 있는지 확인한다.
- Android·iPad에서 리더 하단 시간이 읽는 동안 분 단위로 증가하고 앱 재진입·원격 수신 뒤 감소하지 않는지 확인한다.
- 한 도서를 완독한 뒤 처음부터 다시 읽어 `2회차`가 생기고 `현재`·`완료` 필터가 올바른 회차만 표시하는지 확인한다.
