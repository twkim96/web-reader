# 업데이트 1.6.1 안정화 계획

## 목표

- 1.6.0에서 추가한 PDF, ZIP/CBZ, 7z, Google Drive 대용량 업로드 흐름의 경쟁 조건과 불필요한 부하를 제거한다.
- 빠른 페이지 이동, 화면 크기 변경, 동시 Drive 요청에서도 표시 상태와 저장 상태가 일관되게 유지되도록 한다.
- 신규 형식이나 UI 기능을 추가하지 않고 1.6.0 동작을 안정화한다.
- 기존 TXT/EPUB, 진행률, 북마크, 오프라인 읽기와 클라우드 동기화를 유지한다.

## 현재 상태

- 1.6.0 코드 점검에서 확인된 안정화 항목을 기준으로 작성했다.
- 2026-06-14 기준 Phase 1~6 구현과 자동 테스트를 완료했다.
- 정적 검사, 전체 자동 테스트 61개, 로컬 Chromium 회귀, production build와 HTTP 응답 검증을 통과했다.
- 고정 배포 URL 검증은 배포 작업 범위에 포함하지 않아 미완료로 남긴다.
- 실기기 테스트는 필수 완료 조건에 포함하지 않고 정적 검사, 자동 테스트, 로컬 Chromium 검증과 고정 배포 URL 검증을 사용한다.

## 확정 원칙

1. 비동기 작업은 마지막으로 유효한 사용자 요청만 화면과 진행률을 변경한다.
2. PDF 페이지 렌더는 같은 문서와 배율에 대해 중복 실행하지 않고, 오래된 렌더는 취소하거나 결과를 폐기한다.
3. Drive 폴더 탐색·생성은 계정별 한 요청으로 합치며 같은 이름의 폴더를 중복 생성하지 않는다.
4. Drive 목록 API는 모든 페이지를 읽되, 업로드 배치 중에는 전체 목록 갱신을 반복하지 않는다.
5. 책장 검색과 정렬은 전체 도서 집합에 먼저 적용하고, 화면 표시 단위 제한은 그 결과에만 적용한다.
6. 압축 보호 한도는 이미지 메타데이터뿐 아니라 실제 해제 작업의 메모리와 CPU 위험도 차단한다.
7. 안정화와 무관한 리팩터링, UI 변경, 지원 형식 확대는 하지 않는다.

## Phase 1: 고정 레이아웃 이동 경쟁 제거

### 상태

- 구현, 자동 테스트와 로컬 Chromium 검증 완료.

### 대상

- `public/foliate-js/fixed-layout.js`
- 고정 레이아웃 내비게이션 자동 테스트 또는 전용 회귀 테스트

### 변경

- `goToSpread`의 비동기 페이지 로드에 단조 증가 요청 ID를 부여한다.
- 새 이동 요청이 시작되면 이전 요청의 완료 결과가 iframe, 현재 인덱스, 방향, 진행률을 덮어쓰지 못하게 한다.
- 페이지 로드 성공 전에는 최종 표시 상태를 확정하지 않는다.
- 같은 spread 안에서 좌우 면만 바꾸는 동작은 기존처럼 즉시 처리한다.
- 오래된 요청이 만든 임시 DOM이나 페이지 자원이 있으면 화면에 연결하지 않고 정리한다.
- 마지막 페이지 경계와 연속 키·탭·휠 입력 동작을 유지한다.

### 완료 조건

- 느린 페이지 로드 중 `next → prev`, `prev → next`, 연속 `next`를 실행해도 마지막 요청의 페이지만 표시된다.
- 화면의 페이지, `renderer.index`, relocate 진행률이 같은 섹션을 가리킨다.
- 오래된 비동기 완료가 추가 relocate 이벤트를 발생시키지 않는다.

### 검증

- 서로 다른 지연 시간을 가진 가짜 section loader로 마지막 요청 우선 동작을 자동 검증한다.
- PDF와 압축 도서에서 키보드, 탭, 휠 연속 입력 후 페이지와 진행률 일치를 로컬 Chromium에서 확인한다.

## Phase 2: PDF 렌더 수명과 리사이즈 부하 안정화

### 상태

- 구현, 자동 테스트와 로컬 Chromium 검증 완료.

### 대상

- `public/foliate-js/pdf.js`
- `public/foliate-js/fixed-layout.js`
- PDF 렌더 수명 회귀 테스트

### 변경

- iframe별 현재 PDF.js `RenderTask`와 렌더 세대 번호를 관리한다.
- 같은 페이지의 새 배율 렌더가 시작되면 이전 canvas 렌더를 취소하거나 완료 결과를 폐기한다.
- ResizeObserver 이벤트를 animation frame 단위로 합쳐 같은 프레임의 중복 렌더를 막는다.
- 새 렌더 전에 canvas, text layer, annotation layer와 선택 보조 DOM을 정리한다.
- 취소된 렌더의 예외는 정상 취소로 처리하고 실제 렌더 오류만 상위로 전달한다.
- 페이지 이탈과 도서 닫기 때 진행 중인 렌더, PDF Worker, Blob URL을 모두 종료·회수한다.
- 기존 4페이지 LRU 정책은 유지한다.

### 완료 조건

- 연속 resize 또는 화면 회전 이벤트에도 페이지당 활성 canvas와 텍스트·주석 레이어가 하나만 남는다.
- 오래된 배율 렌더가 최신 화면을 덮어쓰지 않는다.
- 도서 닫기 후 진행 중인 RenderTask, Worker, Blob URL이 남지 않는다.
- 리사이즈 반복 중 처리되지 않은 Promise 오류가 발생하지 않는다.

### 검증

- ResizeObserver를 모의해 중복 렌더 취소와 마지막 배율 우선 적용을 자동 검증한다.
- 로컬 Chromium에서 PDF를 연 뒤 창 크기를 반복 변경하고 DOM 개수, Worker 종료, 콘솔 오류를 확인한다.
- 7페이지 PDF의 목차, 페이지 이동, 진행률, 북마크, 재개 위치 회귀를 확인한다.

- 폴더가 없는 상태에서 동시 요청이 와도 폴더와 appData 레지스트리를 각각 하나만 생성한다.
- 요청 실패 후 in-flight 캐시를 제거해 다음 호출에서 재시도할 수 있게 한다.
- 계정별 캐시 격리와 기존 중복 레지스트리 정리 정책을 유지한다.

- 첫 요청 실패 후 다음 요청은 정상 재시도된다.
- 100개를 넘는 폴더 후보, 레지스트리, 도서도 마지막 페이지까지 처리된다.
- 동명 폴더 충돌과 계정별 canonical 폴더 정책은 기존과 동일하게 동작한다.

### 검증

- 동시 빈 계정 생성, 실패 후 재시도, 계정 전환, 중복 레지스트리 정리를 모의 Google API 테스트로 검증한다.
- 두 페이지 이상의 `files.list` 응답과 반복 `nextPageToken` 방어를 자동 테스트한다.
- 폴더 미확정 상태에서 전체 Drive 조회가 발생하지 않는지 요청 URL로 검증한다.

## Phase 4: 다중 업로드 갱신과 취소 흐름 정리

### 상태

- 구현 및 배치 helper 자동 검증 완료. 고정 배포 URL 검증 대기.

### 대상

- `src/components/shelf/FileUploader.tsx`
- 필요 시 업로드 배치 전용 helper
- Drive 업로드 및 배치 테스트

### 변경

- 파일별 업로드 성공 시 `onRefresh`를 호출하지 않고 전체 배치 종료 후 한 번만 호출한다.
- 한 파일이 로컬 저장에 실패해도 다음 선택 파일 처리 여부와 최종 갱신 규칙을 명확히 유지한다.
- 취소 시 진행 중 요청을 중단하고 이후 파일을 시작하지 않는다.
- 인증 만료 시 이후 업로드를 중단하고 로컬 저장 정책은 기존 동작을 유지한다.
- 여러 파일의 진행률 상태가 이전 파일의 늦은 콜백으로 덮어쓰이지 않게 업로드 세대 또는 현재 파일 검사를 둔다.

### 완료 조건

- 일반 도서 10개 업로드에서 Drive 전체 목록 조회는 배치 종료 후 한 번만 발생한다.
- 업로드 취소 후 새 파일 전송과 늦은 진행률 갱신이 발생하지 않는다.
- 일부 로컬 저장 실패, 401, 403, 재시도 경로에서 책장과 진행률 표시가 실제 결과와 일치한다.

### 검증

- 다중 성공, 중간 취소, 인증 만료, 한 파일 실패를 모의해 업로드 호출 수와 `onRefresh` 호출 수를 자동 검증한다.
- 기존 resumable session, 308, 청크 범위, 재시도, 취소 테스트를 유지한다.

## Phase 5: 압축 해제 보호 한도 보강

### 상태

- 구현 및 공통 보호 로직 자동 검증 완료.

### 대상

- `src/lib/archiveImageBook.ts`
- `src/lib/sevenZipImages.ts`
- `public/7z/archive-worker.js`
- `tests/archiveImages.test.mjs`

### 변경

- 7z 엔트리 목록에서 전체 예상 해제 용량과 비이미지 엔트리를 포함한 위험도를 계산한다.
- 비정상, 음수, 정밀 범위를 벗어난 크기는 손상된 압축으로 거부한다.
- solid 7z는 선택 이미지 앞의 같은 solid block 해제 비용을 정확히 알 수 없으므로 보수적인 전체 해제 용량 한도를 적용한다.
- 실제 추출 결과 Blob 크기가 인덱스의 선언 크기와 보호 한도를 넘으면 페이지로 전달하지 않고 Worker를 종료한다.
- Worker 오류·종료 시 대기 중 요청을 모두 거부하고 MEMFS 출력 디렉터리를 정리한다.
- ZIP/CBZ의 기존 이미지 수, 단일 이미지 100MB, 이미지 합계 2GB 제한은 유지한다.

### 완료 조건

- 작은 이미지와 대용량 비이미지가 섞인 위험한 solid 7z가 해제 전에 차단된다.
- 선언 크기와 실제 추출 크기가 다른 항목은 캐시되거나 표시되지 않는다.
- 실패 후 Worker와 임시 출력 파일이 남지 않는다.
- 정상 혼합 ZIP/CBZ/7z의 이미지 필터와 자연 정렬은 유지된다.

### 검증

- 음수·비정상 크기, 전체 해제 한도 초과, 실제 추출 크기 불일치, Worker 실패를 자동 테스트한다.
- 정상 혼합 압축, 이미지 없음, 암호화, 손상 파일 회귀 테스트를 유지한다.

## Phase 6: 대량 책장 검색·정렬·점진 표시

### 상태

- 구현, 검색·정렬·페이지 경계 자동 테스트와 로컬 Chromium 검증 완료.

### 대상

- `src/components/shelf/bookUtils.ts`
- `src/components/shelf/useFilteredBooks.ts`
- `src/components/ShelfSearchModal.tsx`
- `src/components/shelf/index.tsx`
- 필요 시 책장 파생 데이터 전용 hook 또는 helper
- 책장 검색·정렬 자동 테스트

### 처리 순서

책장 데이터는 다음 순서를 고정한다.

1. Drive 페이지네이션과 로컬 병합으로 전체 도서 메타데이터를 만든다.
2. 도서별 검색 키, 표시 제목, 원본 순서, 읽는 중 여부, 최근 읽은 시각을 한 번 계산한다.
3. 전체 도서에서 검색 조건을 적용한다.
4. 검색 결과 전체에 현재 정렬 정책을 적용한다.
5. 정렬 완료된 결과에서 현재 화면에 표시할 구간만 자른다.

- 표시 구간을 먼저 자른 뒤 검색하거나 정렬하지 않는다.
- 검색 결과 개수는 현재 렌더된 수가 아니라 전체 일치 도서 수를 표시한다.
- 검색 미리보기와 전체 책장은 같은 정규화 및 정렬 helper를 사용한다.

### 검색 정책

- 현재처럼 확장자를 제거하고 공백과 대소문자 차이를 무시하는 제목 검색을 유지한다.
- 도서 배열이 바뀔 때만 도서별 정규화 검색 키를 다시 만들고, 키 입력마다 모든 제목을 반복 정규화하지 않는다.
- 검색 모달 입력은 `useDeferredValue` 또는 짧은 debounce로 렌더 우선순위를 낮추되, 제출한 검색어는 즉시 전체 결과에 반영한다.
- 검색 미리보기는 전체 일치 결과를 현재 정렬 정책으로 정렬한 뒤 상위 5개만 표시한다.
- 검색어를 지우면 전체 도서와 현재 정렬 상태로 복귀한다.
- 검색 중 정렬 모드를 바꾸면 같은 검색 결과 집합만 새 정렬 순서로 재배치한다.

### 정렬 정책

- 로컬 전용 도서와 클라우드 도서를 먼저 하나의 전체 도서 집합으로 병합한다.
- 현재 정책대로 표시용 진행률이 `0% 초과, 100% 미만`인 도서만 읽는 중 그룹으로 분류해 상단에 표시한다.
- 진행률이 0% 또는 100%인 도서는 `lastRead`가 있어도 읽는 중 그룹에 포함하지 않는다.
- 최신순에서는 읽는 중 그룹의 로컬·클라우드 도서를 `lastRead` 내림차순으로 함께 정렬한다.
- 최신순의 읽는 중이 아닌 도서는 Drive·로컬 병합 후의 원본 순서를 안정적으로 유지한다.
- 가나다순은 현재처럼 읽는 중 그룹을 먼저 표시하고, 각 그룹 안에서 표시 제목을 `ko-KR` 기준으로 정렬한다.
- 비교 함수 안의 `books.indexOf()` 호출을 제거하고 원본 순서 인덱스를 파생 데이터에 저장한다.
- 정렬 비교 중 제목 변환, 날짜 파싱, 진행률 반올림을 반복하지 않는다.
- 동일 입력에서 항상 같은 순서를 반환하도록 마지막 tie-breaker로 원본 순서와 도서 ID를 사용한다.

### 점진 표시 정책

- 정렬된 전체 결과를 한 번에 `BookCard`로 렌더링하지 않는다.
- 최초에는 50권만 표시하고 책장 하단 접근 시 다음 50권을 추가한다.
- `IntersectionObserver`가 없거나 실패하면 명시적인 `더 보기` 버튼으로 같은 동작을 제공한다.
- 검색어, 정렬 모드, 보기 모드, 계정 또는 전체 도서 배열이 바뀌면 표시 구간을 첫 50권으로 초기화한다.
- 추가 표시 중에도 이미 계산한 전체 검색·정렬 결과를 재사용한다.
- 그리드와 리스트 모드는 같은 표시 구간을 사용하며 기존 카드 UI와 행 UI를 유지한다.
- 전체 결과를 끝까지 표시한 뒤에는 observer와 추가 로드 상태를 정리한다.
- 1.6.1에서는 새 가상화 라이브러리를 추가하지 않고 점진 표시로 초기 DOM과 React 렌더 비용을 제한한다.

### 완료 조건

- 1,000권 메타데이터에서 검색어 입력, 가나다순·최근순 전환, 검색 초기화가 긴 메인 스레드 정지 없이 동작한다.
- 로컬 전용 도서 100권과 클라우드 도서 1,000권을 병합한 뒤 최신순에서 양쪽의 읽는 중 도서가 `lastRead` 기준의 하나의 시간순 목록으로 정렬된다.
- 진행률 0%와 100% 완료 도서는 `lastRead` 유무와 관계없이 읽는 중 도서보다 먼저 표시되지 않는다.
- 검색 결과 전체의 순서가 확정된 최신순·가나다순 정책과 일치한다.
- 첫 화면에는 최대 50개 `BookCard`만 렌더되고 하단 접근마다 50개씩 늘어난다.
- 두 번째 표시 구간에 있는 도서도 검색하면 첫 결과 구간에 정상적으로 나타난다.
- 검색 결과 개수와 화면에 점진 표시된 개수가 구분되어 표시된다.
- 정렬 모드 변경 후 첫 구간이 새 정렬 결과의 첫 50권으로 교체된다.

### 검증

- `filterAndSortBooks`의 읽는 중 우선, 로컬·클라우드 통합 최신순, 가나다순, 원본 순서 tie-breaker를 자동 테스트한다.
- 진행률 0%, 50%, 100%와 `lastRead` 유무 조합에서 50% 도서만 읽는 중 그룹에 포함되는지 자동 테스트한다.
- 1,000권에서 검색 키가 도서 변경 시 한 번만 준비되고 키 입력마다 반복 생성되지 않는지 검증한다.
- 검색 후 정렬, 정렬 후 검색이 같은 최종 결과를 만드는지 검증한다.
- 표시 구간 밖 도서 검색, 검색 초기화, 정렬 전환, 50권 경계와 마지막 부분 구간을 자동 테스트한다.
- 로컬 Chromium에서 1,000권 모의 메타데이터로 검색 입력, 정렬 전환, 스크롤 추가 표시와 DOM 카드 수를 확인한다.
