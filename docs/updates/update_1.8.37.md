# Web Reader 1.8.37 — 진행률 임시 이동·본문 미리보기

작성일: 2026-09-09

상태: 구현 완료 · 로컬 자동검증 통과

## 본문 바깥 여백까지 배경 통일 — 2026-11-07

- 사용자 후속 사진에서는 본문 안의 띠 대신 본문 사각형과 바깥 좁은 여백의 색 차이가 남았다. 사진의 큰 상하 회색 영역은 갤러리에서 가로 이미지를 세로로 띄운 배경임을 사용자에게 확인했으므로 앱 영역과 구분했다.
- 앞선 수정은 iframe 내부 바탕을 통일했지만, 실제 앱 바깥 화면과는 별도로 칠하고 있었다. `useFoliateLayout`에서 본문 바탕도 투명하게 하여 기존 `EpubReader` 배경색·질감이 본문·간격·바깥 여백 전체에 이어지게 했다. 현재 계약은 [화면 사양](../SPEC/interface.md#테마설정재질)에 유지한다.
- 실제 앱의 게스트 샘플 도서를 여는 회귀에서 수정 전 별도 불투명 바탕을 확인했고, 수정 후 Chromium에서 부모 화면 색 변경이 iframe과 바깥 여백에 그대로 반영되는 픽셀 검사가 통과했다. Chromium/WebKit의 독립 렌더러 투명도·배경·두 페이지 비율 검사까지 5건 통과했다. 로컬 macOS WebKit의 실제 앱 경로 1건은 EPUB Blob 저장 fixture가 리더 시작 전에 실패하여 제외했으며 [개발 가이드](../development/setup-and-checks.md#검증-선택)에 제한을 남겼다. 삼성 PWA 실기기의 남은 색 차이 확인은 [TODO](../TODO.md)에 유지한다.

- 변경 파일 lint와 TypeScript를 포함한 production build도 통과했다.

## 두 페이지 배경 띠 방지 — 2026-11-06

- 삼성 인터넷 PWA에서 두 페이지의 중앙·좌우 여백이 더 어둡다는 사용자 화면을 확인했다. 사용자는 브라우저 강제 다크 모드 없이 시스템 다크 모드만 사용했다고 확인했다. 도서 배경 충돌로 같은 모양을 PC에서 재현했으나 실제 기기의 원인까지 확정한 것은 아니다.
- 본문과 간격을 하나의 문서 바탕에서 칠하고 본문 배경은 투명하게 처리한다. 테마 배경을 inline `!important`로 적용해 도서의 루트/본문 배경이 일부만 덮는 것을 막는다. 현재 계약은 [화면 사양](../SPEC/interface.md#테마설정재질)에 유지한다.
- 검증: Chromium/WebKit의 새 배경 픽셀 검사와 기존 최초 스타일 적용·고정 레이아웃 검사 6건이 통과했다. 기존 두 페이지 비율 회귀도 두 브라우저에서 통과했다. 배경 검사는 시스템 light/dark, 테마·장·페이지/스크롤 전환과 질감을 포함한다. WebKit의 스크린샷 배율을 CSS px로 맞춰 같은 화면 좌표를 비교했다. 변경 앱/타입/테스트 lint와 TypeScript를 포함한 production build도 통과했다. 실제 삼성 PWA의 띠 해소는 [TODO](../TODO.md)에서 별도 확인한다.

## 동작

- 슬라이더를 놓으면 본문은 선택 위치로 이동하고 확인 패널을 표시한다. 확인 전에는 새 위치를 진행도·동기화에 저장하지 않는다.
- 여러 번 움직여도 최초 출발 위치를 유지한다. 30→40→50→60에서 취소하면 30으로 돌아간다. 확인하면 현재 임시 위치와 최초 위치의 자동 책갈피를 저장한다.
- 확인 패널은 바깥 클릭으로 닫히지 않으며 배경 입력이나 키보드 포커스를 가두지 않는다. 진행률·목차·검색·책갈피 메뉴를 계속 사용할 수 있다. 임시 상태의 메뉴 이동도 같은 순서로 실행해 취소·확정과 경합하지 않게 한다.
- 임시 상태에는 자동 저장, 강제 저장, 화면 숨김·종료 저장, 외부 progress flush와 원격 진행률 이동을 차단한다. 취소 시 원래 대기 중이던 저장은 복원한다. 수동 책갈피 편집은 독립적으로 유지한다.
- 드래그 중 화면 중앙에 약 절반 크기의 반투명 미리보기를 표시한다. EPUB/TXT는 해당 위치 근처 본문, PDF/ZIP/CBZ/7z는 해당 페이지 이미지를 보여 준다. 텍스트는 장 내부 문자 비율을 사용하므로 실제 페이지 시작 문장과 완전히 같지는 않을 수 있다.
- 미리보기는 독립 소스로 추출하며 본문을 이동하지 않는다. 요청 지연·직렬 실행·취소와 임시 URL 해제로 오래된 결과 및 이미지 자원 누적을 막는다.

## 정밀 진행률 이동

- 누르는 순간에는 현재 진행률을 유지한다. 짧은 탭은 손을 뗄 때 찍은 위치로 이동하고, 드래그는 현재 진행률에서 손의 가로 이동량만큼 움직인다. 움직임 없이 350ms 누르면 찍은 위치를 새 시작점으로 선택하고, 이후 드래그를 그 위치에서 이어간다. 누른 채 바 위쪽으로 48px 이상 올리면 수평 이동 감도를 1/5로 낮추고, 바 아래쪽으로 48px 이상 내리면 1/10로 낮춘다.
- 정밀 이동 진입·종료에서 현재 선택 위치를 이어받아 위치가 튀지 않는다. 다시 바 쪽 24px 이내로 내려오면 일반 감도로 복귀하며, 다음 새 터치도 현재 진행률에서 시작한다.
- 진입/종료 경계를 다르게 두어 손떨림으로 모드가 반복 전환되지 않게 하고 작은 움직임을 누적한다. 현재 모드는 `일반 이동`, `1/5 정밀 이동`, `1/10 정밀 이동`만 표시하며 미리보기와 분리한 화면 하단의 작은 타원 배지로 표시한다. 기존 메뉴의 글래스 재질을 사용하고 미리보기보다 위에 표시하며 터치를 가로채지 않는다.
- 실제 pointer 이벤트 회귀 9개 통과: 일반 이동, 위쪽 1/5·아래쪽 1/10 감도, 수직 전환 위치 유지, 경계 떨림, 복귀 감도, 새 터치 초기화와 기존 임시 이동 계약.

- 수직 방향이 뚜렷한 드래그와 감도 전환에서는 진행률을 고정한다. 가로 흔들림을 버리고, 좌우 이동 의도가 확인되면 현재 위치에서 해당 감도로 이어간다. 작은 좌우 움직임도 누적해 느린 정밀 이동을 허용한다.

## 도서 형식 필터

- 정렬·필터에서 도서 출처 위에 TXT, EPUB, PDF, ZIP 복수 선택을 추가했다. 선택하지 않으면 전체 형식을 보여주며 출처·장르·태그 조건과 함께 적용한다.
- 변환된 TXT는 원본 형식으로 분류하고 이미지 압축 도서(ZIP/CBZ/7Z)는 ZIP에 묶는다. 카탈로그 로딩 상태와 관계없이 사용할 수 있으며 선택 수·검색·초기화에도 반영한다.

## PDF 브라우저 호환성

- `Map/WeakMap.getOrInsertComputed`가 없는 브라우저에서 PDF 열기가 실패하는 문제를 수정했다. PDF.js 실행 전에 호환 함수를 설치하며 실제 Worker에도 별도 진입점에서 적용한다. 브라우저가 이미 지원하면 기존 함수를 유지한다.

## 압축 표지 보기와 도서 정보 버튼

- 기존 그리드 보기를 일반 표지와 같은 2:3 세로형 압축 표지 보기로 대체했다. 표지 안에 제목·형식·태그·진행률을 겹쳐 표시하고 저장된 그리드 설정도 이 보기로 이어진다.
- 표지 보기와 압축 표지 보기의 오른쪽 위, 일반 목록의 확장자 왼쪽에 세로 점 세 개 버튼을 추가했다. 기존 길게 누르기와 같은 도서 정보창을 열며 본문 열기와 분리된다.


## 시작 위치 복원 검증과 경량 진단

- EPUB 저장 위치의 좌표가 없거나 실제 페이지 이동이 성립하지 않으면 성공으로 처리하지 않는다. 안정화 뒤에도 원래 목표를 다시 확인하며, 없는 CFI 범위를 첫 페이지로 대체하지 않는다.
- 도서 로딩 중에만 저장 위치와 대체 앵커를 최대 두 차례 순회한다. 끝내 실패하면 오류를 알리고 서재로 돌아가며, 읽기 시작 후 지연된 재시도로 위치를 바꾸지 않는다.
- 실패가 있었던 열기만 결과(복구/실패), 시도 횟수, 해시화된 목표 식별값, 페이지·좌표 유무·화면 크기를 최근 8건까지 로컬에 보관한다. 전체 로그·본문·원본 CFI는 보관하지 않으며 정상 열기에는 기록을 쓰지 않는다. 재시작 후 독서 통계의 진단 JSON으로 내보낼 수 있다.
- Chromium/WebKit에서 좌표 없는 CFI 거부, 대체 앵커 복원, 재진입 복원을 페이지 넘김(LTR/RTL)·스크롤 모드로 검증한다. 이 방어는 재현된 실패 경로를 다루며 실제 사용자 도서에서 발생한 간헐적 원인은 경량 기록으로 추가 확인한다.
- 검증: Foliate 샌드박스 Chromium/WebKit 38개(새 회귀 8개 포함), 포맷 Node 80개, 복원·진단·동기화 판단 집중 Node 34개, production build 및 변경 파일 lint 통과. 전체 lint는 기존 `tests/remoteProgressPrompt.test.mjs`의 render 중 외부 변수 대입 오류 2건으로 실패하며 이번 수정에서는 변경하지 않았다.

## 재진입 후 0% 관측 후속 — 2026-10-07

- 2026-10-06 사용자 진단의 두 열기는 TXT 변환 EPUB 캐시·첫 장·복원 성공으로 끝났으며 개별 진행률·이전 위치·빌드 정보는 없었다. 실제 원인이나 이전 위치 복구를 이 JSON만으로 확정하지 않는다.
- 재현 테스트에서 사용자 이동 없는 첫 위치/레이아웃 relocate가 외부 강제 flush로 저장되는 경로를 확인했다. 현재 위치 저장에는 사용자 변경을 요구하고, 변경 없는 flush는 쓰기 없이 성공한다. 실제 처음으로 이동·임시 이동 확인은 저장한다.
- 요청 진행률이 남아 있는데 실제 첫 위치가 열린 성공 반환을 제한적으로 거부하고 기존 대체 앵커·로딩 중 재시도를 사용한다. 기준과 현재 계약은 [리더 사양](../SPEC/reader-and-progress.md)에 유지한다.
- 다음 진단에 빌드 식별자, 요청·실제 진행률, 해시화한 도서·목표·앵커를 포함한다. 정상 열기에 영구 로그를 추가하지 않는다.
- 검증: 수정 전 저장 경로 회귀 3건 실패를 확인하고 수정 후 관련 Node 37개, 기존 Chromium/WebKit CFI 복원·거부 8개, TypeScript·변경 파일 lint·production build가 통과했다. 기존 전체 lint/브라우저 CI 실패와 실제 기기 재발·복구 확인은 [TODO](../TODO.md)에 남긴다.

## 느린 재실행의 계정 복원 순서 — 2026-10-08

- Firebase 응답 지연으로 게스트 서재에서 자동 열기한 뒤 로그인 계정으로 전환되면, 계정 진행률을 읽기 전에 owner/book key 변경으로 리더가 생성되는 경로를 확인했다. 리더의 열기 effect가 빈 시작 위치를 고정하므로, 뒤늦게 들어온 진행률만으로 본문이 복원되지 않는다.
- 계정별 로컬 복원 완료 전에는 리더 생성을 보류하고 기존 로딩 화면을 사용한다. 인증 callback 지연과 계정 복원 지연을 분리한 React 회귀에서 기존 조건의 조기 생성 실패를 확인했으며, 변경 후에는 계정 진행률 60%로 시작한다. 실제 메모리 종료·사용자 기기의 원인 확인은 [TODO](../TODO.md)에 남긴다.
- 열기 성능 진단에 소유자 해시를 추가해 같은 도서의 게스트/계정 열기를 구분한다. 사용자 계정이나 도서 데이터를 변경·삭제하지 않는다.
- 전환 전 리더의 미저장 위치가 종료 저장 callback까지 전달되는 경로도 회귀에서 재현했다. 저장 직전에 리더의 원래 owner/generation을 확인해, 이미 활성화된 다른 계정으로 이전 리더의 위치를 저장하는 것을 막는다. 같은 owner/generation의 정상 저장은 유지한다.
- 검증: 조기 리더 생성·전환 전 종료 저장의 새 회귀가 수정 전 각각 실패하고 수정 후 통과했다. 관련 Node 실행은 35개 통과·기존 원격 안내 테스트 1개 실패이며 해당 실패는 `83b4d9b` 원본에서도 재확인했다. 변경 파일 lint와 TypeScript를 포함한 production build는 통과했다. 기존 실패의 대응과 실제 기기 확인은 TODO에 유지한다.
