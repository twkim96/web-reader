# 마이페이지 계정 저장과 공유 설계

기존 마이페이지 주소와 화면을 유지합니다. 위시리스트와 내 평가는 로그인 계정에서 이어서 사용하고, 다른 사람에게 보일 항목은 사용자가 선택합니다. 이 문서는 로컬에서 구현한 Firestore 저장 구조와 공개 계약을 설명합니다. 현재 시안의 저장과 조회 동작은 [서재 사양](../SPEC/library-and-files.md#마이페이지-로컬-시안)을 따릅니다.

## 닉네임과 공개 마이페이지

처음에는 `행복한사자`처럼 무작위 닉네임을 지정합니다. 사용자는 닉네임을 수정할 수 있습니다. 닉네임 중복을 허용하고, 계정마다 한 번 발급하는 고유 ID 코드로 구분합니다. 표시는 `행복한사자#7K4M2Q8R` 형식입니다. 닉네임을 바꿔도 코드와 프로필 주소는 유지됩니다. 발급할 때 서버가 코드의 고유성을 확인합니다.

작품 상세의 공개 평가에서 닉네임을 누르거나, 사람 검색에서 닉네임 또는 ID 코드로 검색한 결과를 누르면 같은 공개 마이페이지로 이동합니다. 닉네임이 같은 검색 결과에는 ID 코드를 함께 표시합니다. 상대가 아래 세 항목 중 켠 것만 표시하며, 전부 꺼진 계정은 사람 검색과 공개 마이페이지에 표시하지 않습니다.

| 설정 | 켰을 때 보이는 정보 |
| --- | --- |
| 별점 및 평가 공개 | 작품 상세와 내 공개 마이페이지에서 별점과 선택 한줄평이 보입니다. 작품 상세에는 서버가 확인한 독서 시간과 진행률도 함께 표시합니다. 별점만 남긴 평가도 공개 및 집계 대상입니다. |
| 읽은 책 공개 | 메타데이터와 연결된 읽은 책과 읽고 있는 책을 보여 줍니다. 공개 목록에는 작품과 독서 상태를 표시합니다. |
| 위시리스트 공개 | 현재 위시리스트가 보입니다. 공유하려면 공개 마이페이지의 주소를 전달할 수 있습니다. |

세 설정은 기본 비공개인 계정 단위 설정입니다. **별점 및 평가 공개**를 끄면 모든 작품 평가가 개인 저장용으로 전환됩니다. 다른 사람의 화면, 작품 평균, 평가 개수에서 모두 제외됩니다. 작품 평균에는 공개된 별점만 들어가며, 한줄평 유무와 관계없이 계정당 작품별 별점 하나를 집계합니다. 공개 평가가 0개면 평균을 표시하지 않습니다.

## 저장 구조

비공개 문서의 기준 경로는 `artifacts/{appId}/users/{uid}/libraries/local`입니다. `workId`는 공개 메타데이터의 작품 ID를 쓰고, 문서 키 `workKey`는 이 ID의 해시를 사용합니다. 파일명이 달라도 같은 작품이면 위시리스트와 평가는 각각 한 건입니다. 게시 인덱스에서 같은 플랫폼 링크로 연결된 작품 키를 하나로 묶습니다. 탐색과 상세에는 묶인 작품의 모든 플랫폼 링크를 유지합니다. 기존 키가 새 게시 인덱스에서 사라지는 경우의 영구 리디렉션은 후속 작업입니다.

| 비공개 문서 | 저장할 값 |
| --- | --- |
| `myPageWishlistV1/{workKey}` | 작품 ID, 추가 시각 |
| `myPageReviewsV1/{workKey}` | 작품 ID, 별점, 선택 한줄평, 수정 시각. 독서 근거를 공개할 때 서버가 확인한 독서 시간과 진행률을 함께 보관합니다. |
| `readingStatsV1/{sessionId}` | 동기화된 기존 독서 세션. 서버가 공개 카탈로그의 작품 ID와 독서 상태를 집계합니다. |
| `myPageSharingV1/settings` | 계정에 연결된 고정 ID 코드. 닉네임과 공개 설정 및 버전은 서버 전용 프로필 문서가 보관합니다. |

| 공개 조회 | 서버가 제공할 값 |
| --- | --- |
| 사람 검색·공개 마이페이지 | `publicReaderProfilesV1/{publicCode}`를 사람 검색과 프로필 조회에 사용합니다. 닉네임으로 찾거나 ID 코드를 정확히 입력해 찾을 수 있습니다. 코드와 계정 UID의 연결은 서버 전용 경로에서 관리합니다. |
| 공개 위시리스트 | 서버가 현재 위시리스트 공개 설정을 확인한 뒤 보관 중인 목록의 작품 ID와 표시 순서를 반환합니다. 공개 중 추가·제거한 작품도 반영됩니다. |
| 공개 읽은 책 | 공개 설정이 켜진 계정의 동기화 세션에서 서버가 작품 ID와 독서 상태를 제공합니다. |
| 공개 평가한 책 | 계정 단위 평가 공개 설정으로 조회를 제한합니다. 작품 ID, 별점, 선택 한줄평을 제공합니다. |
| 작품별 공개 평가 | 기존 `publicBookReviewsV1/{workKey}/entries/{entryId}`를 사용합니다. 별점, 선택 한줄평, 검증한 독서 시간과 진행률에 작성자의 현재 닉네임과 공개 ID 코드를 붙입니다. 서버는 계정과 작품 조합마다 한 건을 유지합니다. |

## 조회와 변경

- 공개 프로필 URL에는 고정 ID 코드를 사용합니다. Firebase UID, Google 계정 정보, 개인 파일명, 책갈피, 세션 원본은 비공개 경로에 보관합니다. 공개용 문서는 서버만 읽고 쓰며, 조회 API는 현재 공개 범위를 확인하고 허용된 필드만 반환합니다. Firestore Rules의 읽기 권한은 문서 단위로 평가됩니다. [Firebase 필드 보호 문서](https://firebase.google.com/docs/firestore/security/rules-fields)
- 위시리스트와 평가는 계정·작품별 문서로 만들면 다른 작품을 수정할 때 서로 덮어쓰지 않습니다. 동일 작품의 평가 변경과 공개본 갱신은 하나의 서버 트랜잭션으로 처리합니다. [Firebase 트랜잭션 문서](https://firebase.google.com/docs/firestore/manage-data/transactions)
- 사람 검색, 공개 프로필, 작품별 평가와 평균은 조회 시점의 계정 설정을 적용합니다. 초기 평균은 현재 평가 공개가 켜진 계정의 별점만 서버에서 세어 산출합니다. 평균은 모든 공개 평가를 대상으로 하며, 화면에는 평가를 페이지 단위로 표시합니다. 집계 캐시를 도입할 때는 현재 공개 설정이 반영된 값을 제공합니다.
- 공개 응답에 `Cache-Control: no-store`를 적용합니다. 비공개 전환 뒤 남은 공개용 문서를 정리할 수 있으며, 비동기 집계는 공개 설정의 최신 버전을 확인해 이전 작업이 콘텐츠를 다시 노출하지 않게 합니다.
- 공개 화면은 계정이나 작품 하나를 기준으로 목록을 페이지 단위로 표시합니다. 공개 독서 목록과 평가 증빙은 동기화 세션의 서버 집계를 짧게 재사용합니다. 기기에서 숨긴 독서 통계는 서버에 전달되지 않으므로 공개 설정에 이를 알립니다.
- 기존 브라우저의 평가와 위시리스트는 로그인 뒤 사용자가 가져오기를 선택할 때 계정에 복사합니다. 저장된 플랫폼 링크를 우선 확인하며 제목만 남은 평가는 유일하게 확인되는 작품에 연결합니다. 계정 기록이나 삭제 기록이 이미 있으면 유지합니다. 일반 변경에서는 사용자가 확인한 버전 번호를 비교하고, 삭제 뒤에 다시 등록할 때도 최신 삭제 버전 번호가 필요합니다. 가져올 항목의 공개 설정이 이미 켜져 있으면 가져온 내용도 보인다는 점을 확인 화면에 표시합니다.

## 데이터베이스 선택

현재 필요한 조회는 한 계정의 목록과 한 작품의 평가입니다. 기존 Firebase 인증, 작품 메타데이터, 독서 세션을 같은 Firestore에서 연결하는 편이 운영 부담이 작습니다. 공개 목록처럼 조회 기준이 다른 경우에만 필요한 값의 사본을 관리합니다. 팔로우 관계를 가로지르는 피드, 여러 사용자 목록의 교집합, 다양한 조건을 결합한 추천과 랭킹이 핵심 기능이 되면 PostgreSQL의 조인과 관계 제약을 다시 비교합니다. [PostgreSQL 조인 문서](https://www.postgresql.org/docs/current/tutorial-join.html)

서버 엔드포인트는 `/api/mypage`와 `/api/book-reviews`입니다. 실제 서버에는 Firebase Admin 자격증명이 필요합니다. 계정 저장, 세 공개 설정의 조합, 비공개 평점 제외, 삭제 후 가져오기, 브라우저의 직접 Firestore 접근 차단은 격리된 Firebase 에뮬레이터에서 검증합니다.
