서버가 이미 처리한 이벤트의 성공 응답만 유실될 수 있으므로, lease가 유효한 동안은 중복 처리 증거를 보존합니다. 초기안의 180일 권한과 210일 보존을 90일과 120일로 줄이면서 30일의 운영 여유를 유지했습니다.

후속 [동기화 전체 PRO 리뷰](../updates/review_sync_pro_20261118.md)에서 TTL 전환과 기간 단순화 권고가 나왔습니다. 후속 정확성 수정과 연령순 배치를 구현했습니다. TTL 전환 조건은 [운영 가이드](../operations/deployment-and-recovery.md#유한-동기화와-영수증-정리)에 있습니다.

## 대안 비교

| 방식 | 판단 |
| --- | --- |
| 기기가 마지막으로 연결된 날부터 180일 | 책 B의 활동이 책 A의 오래된 전송 작업까지 연장할 수 있어 단독 기준으로 부적합 |
| 기기별 최근 N개만 보존 | 활발한 기기가 아직 유효한 재전송 증거를 밀어내므로 부적합 |
| 전역 고정 generation | 경계 시각에 여러 기기가 한꺼번에 만료될 수 있음 |
| 기기·대상별 연속 ACK watermark | 빈 번호·여러 탭·DB 복원까지 추적해야 하므로 현재 규모에서는 복잡함 |
| 전체 영수증을 묶음 archive에 영구 보관 | 추가 조회·정리 비용과 영구 이력은 남고 기존 영수증도 바로 줄이지 못함. 채택하지 않음 |
| 이벤트에 고정된 불변 서버 lease | 오래된 작업을 확실히 거절할 수 있어 유한 보존 정책에 적합 |

필요하지 않은 영수증 필드 인덱스를 제외하는 로컬 설정도 추가했습니다. 점 조회와 Rules 필드 검증에는 필드 인덱스가 필요하지 않지만, 현재 나이별 감사에 쓰는 `createdAtServer` 인덱스는 유지해야 합니다. 인덱스 변경도 이번에는 배포하지 않았습니다.

## 채택 계약의 위치

구현된 이벤트 ID·불변 권한·만료 후 최신 수신 계약은 [리더와 진행률](../SPEC/reader-and-progress.md#유한-동기화)에 있습니다. 다른 책 활동이나 재접속으로 과거 이벤트를 연장하지 않습니다.

## 탭 간 대기 저장과 도서 삭제 후속 설계

2026-11-21 Astra·Neon 후속 검토에서 정한 구현 방향입니다. 적용과 실기기 확인은 [TODO](../TODO.md#astraneon-후속-검토)에 남아 있습니다.

- 미발급 이벤트의 권한 연결은 생성 실행의 메모리 증명으로 제한합니다. 생성자가 Web Lock을 획득한 뒤 실행 식별자를 미제출 이벤트와 삭제 intent에 기록하는 방식을 사용합니다. 그 lock이 살아 있는 동안 다른 탭은 claim과 만료를 함께 건너뜁니다. lock을 확보한 복구 탭은 트랜잭션에서 ID와 상태를 다시 읽고, 연결되지 않은 작업의 payload를 보존합니다. 구형 데이터·미지원 환경에서 생존이나 권한을 추론하지 않고 명시적으로 복구할 수 있게 보존합니다.
- 전체 주석 삭제의 수락 세대와 구형 작업 보존 계약은 [주석 사양](../SPEC/annotations-and-tools.md)에 있습니다.
- 오프라인 진행률 병합을 확대할 때는 같은 실행·기기·뷰포트의 마지막 미제출 저장에 한정합니다. 원래 이벤트 ID·권한 발급 시각·기준 revision·선행 위치 토큰은 유지합니다. 신뢰 서버 시간이 없는 앱 시작에서 기존 권한을 자동 재사용하는 범위는 별도로 검증합니다.

## 전환과 정리

1. 로컬에서 네 mutation의 Rules 차단과 progress의 발급→고정→만료 격리→최신 수신을 수직 검증합니다. pure helper 검사만으로 구현 완료를 선언하지 않습니다.
2. 구형 앱과 호환되는 Rules를 먼저 배포하고 새 운영 앱에서 쓰기 권한을 사용합니다. 전환 검증 뒤 모든 경로에서 구형 쓰기를 서버가 거절하도록 변경합니다. 구버전 앱의 대기 작업을 보존하고 업데이트·재수신으로 복귀할 절차가 필요합니다.
3. 구형 쓰기 차단이 실제 적용된 확인 시각을 `T`로 기록합니다. 영수증 생성 시각과 전환 시각 T가 모두 [운영 가이드의 보존 조건](../operations/deployment-and-recovery.md#유한-동기화와-영수증-정리)을 충족해야 정리합니다.
4. 발급 시각·만료 검사와 legacy 차단을 무효화하는 Rules로는 rollback하지 않습니다. 이번 구현은 UID 활동 시 하루 한 번 요청하는 제한된 배치 방식입니다. 정책 전환과 실제 삭제 활성화는 별도 운영 단계입니다. 운영 절차는 [복구 가이드](../operations/deployment-and-recovery.md#유한-동기화와-영수증-정리)에 있습니다.

## 최소 검증

- 만료 직전/정각/직후, 위조 발급 시각, lease 갱신과 같은 ID 재생성 후 옛 이벤트 거절.
- 책 B에서 계속 활동해도 책 A의 옛 작업이 연장되지 않음.
- 서버 적용 후 응답 유실·재전송, 영수증 삭제 뒤 과거 `forceDelete` 재실행 방지.
- 오래된 책 삭제 intent가 새 권한으로 재생성되지 않음.
- 만료 중 재접속, 최신 수신 실패, 여러 탭·구버전·복원된 IndexedDB의 대기 작업 격리와 보존.
- 신규 권한 발급의 Rules 접근 횟수·실제 비용, 전체 mutation gate와 legacy barrier의 emulator 및 다중 기기 수용 확인.

## 로컬 검증 상태

Rules emulator에서 진행률·책갈피·주석·팔레트의 유효/만료 lease, 위조 시각·다른 기기·legacy 차단을 검증했습니다. IndexedDB 회귀는 과거 payload 보존, 최신 상태 수신 실패/동시 작업/owner 전환, 책 전체 삭제 복구와 기존 outbox 보존 migration을 포함합니다. 실제 운영 barrier·다중 기기/PWA 수용 확인은 하지 않았습니다.
