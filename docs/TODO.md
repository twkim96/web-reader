- 운영 배포 전 검증으로 [CI](https://github.com/twkim96/web-reader/actions/runs/44834297956), 로그인한 Edge 프리뷰의 마이페이지·작품 상세 진입, 격리 Firebase 환경에서 동일 계정의 두 브라우저 간 위시리스트·평가 동기화를 확인했습니다.
- 운영 배포 후 설치형 모바일 PWA에서 실제 계정으로 [마이페이지](SPEC/library-and-files.md#마이페이지-로컬-시안)를 확인합니다. 앱 업데이트, 새 인덱스 수신과 오프라인 재진입, 계정 전환, 두 세션의 위시리스트·평가 동기화가 대상입니다. 요청형 제목과 게시 작품 키가 다른 도서의 별점 단독 저장·새로고침·수정·삭제도 확인합니다.
- 같은 실기기 검증에서 홈 추천의 작품·태그 적합성과 첫 표시, 캘린더와 통계의 일치, 삭제된 도서 표시, 작품 상세의 책갈피 접기·펼치기, 연관 도서 스와이프·상세 이동, 진행도·별점 바로가기, 주석 목록·내보내기를 확인합니다. 둘러보기의 공개 프로필, 사용자별 평가와 위시리스트, 공개 해제 후 새로고침 시 목록과 작품 평균 반영도 확인합니다.
- 설치형 PWA에서 읽은 책을 처음 연 뒤 앱을 다시 열어 저장된 매칭이 먼저 표시되고 새 제목만 추가 조회되는지 확인합니다. 같은 기기에서 계정을 바꾼 뒤 이전 계정의 목록이 보이지 않는지도 확인합니다.
- 운영 위시리스트 최신순 인덱스와 조회는 확인했습니다. 공개로 담은 도서가 있는 계정에서 피드 최신순을 확인합니다.
- [개인 위시리스트 한 문서 조회](operations/deployment-and-recovery.md#개인-위시리스트-한-문서-조회)를 운영에 켜기 전에 구버전 쓰기 경로의 격리를 확인합니다. 활성화 후 두 기기의 삭제·재등록과 개인 목록의 위시리스트 문서 읽기 수를 확인합니다.
- 운영에서 [공개 프로필 후보 캐시](operations/deployment-and-recovery.md#공개-프로필-후보-캐시)가 적용된 30권 이상인 공개 목록의 더 보기, 평가 수정·삭제와 읽기 절감량을 확인합니다. 작품별 공개 평가가 늘어날 때의 반복 문서 읽기 수로 집계 구조의 변경 여부를 정합니다. 공개 프로필에 여러 페이지를 펼친 뒤 복귀할 때 목록과 공개 해제 반영을 함께 확인합니다. 설치형 모바일에서 로그인한 계정의 마이페이지 첫 진입·1분 내 재진입·1분 이후 복귀를 비교합니다. 목록 API 횟수와 첫 행·편집 가능 시점을 확인하고, 도서목록 첫 표시와 큰 이력의 로컬 계산이 오래 걸리면 [UI 계측](development/setup-and-checks.md#완료-증거)으로 인덱스 처리·타임라인·인증 시간을 대조합니다. 두 개인 요청의 병렬 실행이 화면 대기를 지배하는지 확인한 뒤 통합 API를 판단합니다. [운영과 Chromium 모의 측정 기준](updates/update_1.8.37.md#마이페이지-운영-계측--2026-11-21)을 비교에 사용합니다.

## 독서 통계 사전 집계

- [자동 등록](operations/deployment-and-recovery.md#공유-예산과-정기-마감)이 적용된 뒤 운영 미등록 계정에서 등록, 최초 이력 수신과 이어받기, 첫 발행, 임시 사본 정리까지 확인합니다. 인증 목록 조회 오류와 주간 배치 예산을 함께 확인합니다.
- [공유 예산과 정기 마감](operations/deployment-and-recovery.md#공유-예산과-정기-마감)의 인덱스와 Cron 연결을 확인합니다. 19주 초안을 준비한 Mac 파일럿의 화요일 오후 6시 KST 기준 첫 마감에서 기존 10주 달력과 마지막 9주＋1주 결과를 실제 저장 내용과 대조하고 읽기 비용을 실측합니다. 최신 증분과 주별 상세·빈 주·주 경계의 늦은 업로드·문서 크기를 확인합니다.
- [발행 달력과 기존 기기 재검사](SPEC/reading-statistics.md#저장동기화출력)를 실제 파일럿에서 확인합니다. 검증용 빌드는 날짜 합계와 선택한 주 상세를 읽으며, 발행 범위와 기존 원본 커서를 확인한 경우 28일 원본 전수 검사를 대신할 수 있습니다. 파일럿 계정의 시작 범위 인증 여부와 `publishedAudit`·`fullScanReason`·실제 반환 문서 수를 기록합니다.
- 실제 파일럿에서 [도서별 합계와 평가 증빙](SPEC/reading-statistics.md#저장동기화출력)을 원본과 대조합니다. 마감 전후의 업로드, 평가 증빙의 원본 전환 빈도, 집계 문서 크기와 조회 수를 확인합니다.
- 실제 파일럿에서 기간별 통계·전체 통계·JSON의 날짜별 및 도서별 합계를 대조합니다. 최근 기간에서는 해당 주 상세만, 전체와 JSON에서는 누적 도서 합계만 읽는지 확인합니다.
- 첫 독서 이력까지 발행된 파일럿 계정을 기존 PWA와 새 브라우저 프로필에서 비교합니다. iPad에서 기존 집계를 다시 적용해 2주 표시가 해제되는지, 다음 정기 마감에서 경계에 걸린 지연 기록을 제외하고 정상 기록을 표시하는지 확인합니다. 발행 누락과 구형 PWA 전환에서 14일 복구 커서, 집계 복구 뒤 전체 JSON 활성화도 확인합니다.
- 화면 독서의 5분 확정과 탐색 전 경계를 설치형 PWA에서 확인합니다. 다른 기기 수신 지연과 이 기기의 초안 복구를 구분해 기록합니다.

## PRO 리뷰 후속 동기화 정확성

- iPad PWA에서 [복구 옵션](SPEC/reader-and-progress.md#동기화와-충돌)으로 중단된 기록을 확인하고 선택한 서버 상태를 수신한 뒤 다음 저장이 전송되는지 확인합니다. 앱 업데이트 직후에는 달력을 열린 채로 두고 확정 집계가 자동으로 표시되는지 확인합니다. 과거 기록이 계속 비어 있으면 [진단](SPEC/reading-statistics.md#진단)에서 집계 설치 여부와 최근 복구 상태를 대조합니다.

- [통합 리뷰](updates/review_sync_pro_20261118.md) 후속의 화면별 인과 기준·비동등 위치 충돌·늦은 무시/이동 guard·권한 준비/만료 분리·유효 후속 의도 보존을 구현했습니다. 실제 두 기기/다중 탭의 R2 창→R3 수신→이동·무시·실패 재시도, 다른 화면의 ACK 중 과거 화면 저장을 Android/Samsung Internet·iPad PWA에서 확인합니다. 업데이트된 운영 앱에서 새 쓰기 권한으로 동기화가 이어지는지 확인합니다.
- 실제 앱/계정 전환·숨김/복귀와 두 reader의 결과를 기록해야 수용 완료입니다. 자동 IDB·React·Rules 검사는 실제 기기 확인을 대체하지 않습니다. 최종 Astra 리뷰와 자동검증 근거는 위 보고서의 후속 개발 절에서 관리합니다.

### Astra·Neon 후속 검토

- 복구 대기 중인 책갈피·주석·팔레트가 있는 설치형 PWA에서 읽기·저장을 계속할 수 있는지 확인합니다. 자동 이동을 중단한 뒤 책을 다시 열었을 때 유효한 이동 안내만 복원되는지, 다른 기기의 한 페이지 이동이 일반 확인창으로 나타나는지 확인합니다.
- [도서 전체 주석 삭제](SPEC/annotations-and-tools.md)에서 다른 기기의 새 주석 보존, ACK 유실 뒤 정리 재개, 처리 근거가 없는 구형 작업의 보존을 두 기기에서 확인합니다. 두 탭에서 같은 책을 거의 동시에 삭제하고 새 주석이 남는지도 확인합니다. 한 기기에서 지웠다 다시 추가한 책을 마커 캐시가 없는 기기의 서재에서 삭제하는 경우와 업데이트 전 버전의 PWA가 열려 있는 경우도 확인합니다.
- iPad·Android 설치형 PWA에서 [미발급 저장과 오프라인 병합](SPEC/reader-and-progress.md#유한-동기화)을 확인합니다. 절전 중 다른 탭의 claim·만료 건너뛰기, 추적 탭 종료 후 원본 보존과 최신 상태 복구, Web Locks 미지원 시 같은 실행의 온라인 복귀와 재실행 후 원본 보존 및 최신 상태 복구, 그리고 같은 뷰포트의 미제출 진행률 병합을 검증합니다.
- [통계 수신 진단](SPEC/reading-statistics.md#진단)과 [마이페이지 서버 계측](development/setup-and-checks.md#완료-증거)으로 새 기기·주간 건수 대조·주기적 전체 재검사·평가 저장 폴백의 반환 문서 수를 비교합니다. 주간 검사 전에 다른 기기가 기록을 추가한 경우 기존 기록의 전량 조회가 발생하지 않는지, 여러 페이지를 받는 중에도 새 기록이 올라가는지 실기기에서 검증합니다. 자동 수신의 빈 조회 간격이 늘어나는 동안 통계 화면 진입·수동 새로고침·온라인 복귀에서는 즉시 신규 기록을 받는지 확인합니다. 전체 재조회 원인은 `fullScanReason`으로 비교합니다. 온라인 복귀 시 진행률 전역 리스너 재시작은 실제 조회량과 재연결 지연을 측정한 뒤 판단합니다.
- [동기화 진단](SPEC/reading-statistics.md#진단)의 발급 사유와 진행률 리스너 재시작 사유를 Firestore 사용량과 대조합니다. 기기 재실행 때 권한 발급 수와 진행률·주석 전송의 반영·재생·충돌 횟수를 비교합니다. 주석 일괄 삭제에서 느린 전송 때문에 원격 head를 반복 조회하는 경우, 대기 중 조회를 줄여도 충돌·중단·자격 만료 뒤 복구가 끝나는지 검증합니다.

## 리더 여백·공통 헤더 실기기 확인

- 제목 요약 설정의 기본 켜짐·꺼짐 유지와 서재/리더/주석/통계의 표시, 도서 정보의 원래 제목 유지를 Android/iPad PWA에서 확인합니다. 요약이 같은 여러 도서의 구분과 원본 이름을 통한 검색도 포함합니다. 자동검증과 실제 기기 확인을 구분합니다.

- 사용자의 로컬 시안 확인과 배포 요청을 반영했습니다. 실제 Android/iPad에서 기본 4/7 및 1/7~7/7 단계의 좌우·상하 여백, 70% 증가량의 좌우 여백, 공통 헤더·아이콘 액션, 모바일 헤더 끌어 닫기와 크기 상세 확장 강조를 확인합니다.
- 조선일보 명조·조선 굴림·고운바탕·고운돋움의 실제 Android/iPad 표시·오프라인 재열기, 가로 폰트 목록의 터치 스크롤, 시트 본문 스크롤과 헤더 드래그·취소·키보드 표시·화면 회전을 기기에서 확인합니다. 사용자 테마 질감이 본문·서재에는 남고 모달·바텀시트에는 직접 그려지지 않는지(뒤에서 비치는 유리 효과는 유지), 1/7에서 실제 페이지 넘김 뒤에도 옆 페이지 조각이 나타나지 않는지도 확인합니다. 실제 기기·브라우저·빌드별 결과가 완료 조건이며 자동 Chromium/WebKit 결과와 구분합니다.

## 도서 정보 이미지 내보내기 실기기 확인

- 삼성 인터넷에서 설치한 Android PWA의 도서 정보창에서 실제 표지가 있는 책의 PNG 저장과 이미지 복사를 재확인합니다. 온라인·오프라인 모두 저장 파일을 열고, 복사한 이미지를 이미지 붙여넣기를 지원하는 앱에 붙여넣습니다.
- 완료 조건: 브라우저·OS·빌드와 저장/붙여넣기 결과를 기록합니다. [자동 회귀](../tests/e2e/bookInfoImage.spec.ts)의 PNG 픽셀·다운로드·클립보드 API 전달 검사를 실제 삼성 인터넷의 권한·OS 클립보드 수용 확인으로 대체하지 않습니다.

## 압축 이미지 웹툰 모드 실기기 확인

- 통합 및 자동검증 결과와 별도로 실제 iPad Safari와 설치된 PWA에서 ZIP/CBZ/7z의 [웹툰 모드](SPEC/reader-and-progress.md#압축-이미지-웹툰-모드)를 확인합니다. 이미지 비율·폭, 짧은 이미지 여러 장의 연속 스크롤과 역방향 이동, 화면 위 이미지 기준 페이지 진행률과 책 끝의 마지막 페이지를 확인합니다. 크기를 헤더에서 알 수 없는 이미지의 표시, 긴 스크롤 뒤 메모리·반응, 회전과 화면 숨김/복귀도 확인합니다. 120Hz 지원 iPad에서 일반 터치 스크롤의 체감 지연·부드러움과 핀치 확대·명시적 드래그/pan을 확인하며 자동 브라우저 측정만으로 실제 120Hz 동작을 판정하지 않습니다.
- 완료 조건: 기기·OS·브라우저/PWA·빌드별 결과를 기록하고 페이지 CFI로 재열기·이동 시 이미지 맨 위에서 시작하는지, 토글 설정과 PDF/텍스트의 버튼 부재를 확인합니다. 미실행 항목은 남깁니다.

## 자동읽기 실기기 확인

- [자동읽기 사양](SPEC/annotations-and-tools.md#자동읽기)의 Android/iPad PWA 수용 확인은 대기입니다. 실제 긴 EPUB/TXT에서 현재 단어 시작, WPM 변경, 장 전환, 닫기 뒤 위치 저장/재열기, 앱 숨김·복귀의 일시정지를 확인합니다.
- 완료 조건: 실제 기기·빌드와 결과를 남기고, 가로/작은 화면의 중앙 모달·배경 blur·safe-area·긴 단어와 브라우저 back을 확인합니다. Chromium/WebKit 자동검증을 실제 기기 확인으로 대체하지 않습니다.

## 동기화 유효기간과 영수증 정리

- [쓰기 권한 계약](SPEC/reader-and-progress.md#유한-동기화)에 따라 신규 설치·오래된 IndexedDB 복원·구버전 탭 공존·90일 만료 후 네 종류 데이터 복구를 실제 PWA/두 기기에서 확인합니다. 유효한 캐시 권한으로 오프라인 저장을 한 뒤 앱을 재실행한 경우와 만료된 기기에서 새 편집 후 앱을 켜둔 채 다시 연결한 경우를 각각 확인합니다. 서버 권한 없이 생성 실행이 끝난 미제출 작업은 최신 상태 복구까지 확인합니다.
- [운영 가이드에 기록된 120일 유예](operations/deployment-and-recovery.md#유한-동기화와-영수증-정리)가 끝나면, 전환 이후 구형 쓰기가 다시 허용되거나 권한 기간이 소급 연장된 배포가 없는지 확인합니다. 결제 상태와 기존 영수증 처리 비용을 확인해 TTL 또는 한도를 둔 배치의 적용 여부를 결정합니다.
- 완료 조건: 통합된 로컬 검증과 실제 기기 결과, 전환·복귀 절차를 기록합니다. 그 전에는 정리 API와 TTL을 꺼둡니다. 영수증 정리 이후 legacy 허용 Rules로 복귀하지 않습니다.

## 원격 위치 안내 갱신 실기기 확인

- 열린 창이 있는 기기 A를 둔 채 B에서 작은 폭 연속 페이지 이동·초기화·계속 이동한 후 A의 이동하기/무시를 확인합니다. UI·IndexedDB 회귀에서 최신 대상 갱신과 늦은 결과 무시, 과거 화면 저장 방어를 통과했으며 실제 두 기기 수용 확인은 남습니다.
- 이동 중 다시 B에서 변경하거나 A에서 조작하는 경우, 응답 유실 재시도 후 다른 기기 head가 더 최신인 경우를 포함합니다. 완료 조건은 창을 닫고 도서를 다시 열지 않아도 최신 위치를 수락하고, 실패 후 A의 이전 화면 저장이 B의 최신 위치를 조용히 덮어쓰지 않는 것입니다.
- 한 기기에서 종료 직전 넘김 → 자동 열기 → 앞뒤 페이지 이동을 반복합니다. 이어서 iPad → Mac → iPad 순으로 읽으며 클라우드 동기화 창이 상대 기기의 최신 저장 진행률로 갱신되는지, 이동을 누르기 전에는 화면이 움직이지 않는지, 양쪽이 실제로 읽은 위치가 다르면 배지에서 두 위치를 선택할 수 있는지 확인합니다. Android/Samsung Internet과 iPad PWA에서 다른 탭이 먼저 업데이트를 적용해도 각 탭에서 저장을 마친 뒤 새로고침하고 대기 저장이 유지되는지 확인합니다.

## 기존 브라우저 CI 실패

- 페이지 넘김 검사의 outgoing range는 첫 화면의 ResizeObserver가 현재 페이지를 다시 배치하면서 생성했습니다. 검사에서 초기 배치가 안정된 뒤 탭을 측정하도록 수정했고, 두 엔진에서 다음 장으로 바로 이동하며 나가는 장의 range와 relocate를 만들지 않는다는 기존 조건을 통과했습니다.

- 브라우저 회귀의 서재 정보 배치와 본문 선택 메뉴는 현재 [인터페이스 사양](SPEC/interface.md)에 맞춰 검사합니다. 기존 스크롤 모드 전환 실패는 닫힌 툴바의 설정 버튼을 눌러 발생했습니다. 툴바를 연 뒤 설정을 바꾸면 스크롤과 탭 모드 전환을 모두 확인할 수 있습니다.
- Playwright WebKit의 임시 프로필에서는 IndexedDB에 Blob과 File을 쓸 수 없어 일회용 영속 프로필을 사용합니다. 데스크톱 Safari에도 ZIP의 같은 스레드 해제 경로를 적용한 뒤 가져오기·웹툰 위치 저장·복원을 두 엔진에서 확인했습니다. 독서 설정의 글꼴 변경·복원과 서비스 워커 캐시의 오프라인 글꼴 디코딩은 독립적으로 확인합니다. [기준 브라우저 CI](https://github.com/twkim96/web-reader/actions/runs/44769773837)
- Chromium과 WebKit 자동 검사에서 온라인과 HTTP 차단 상태의 도서 정보 PNG 복사·다운로드에 로컬 표지가 들어가는 것을 확인했습니다. 설치형 앱의 실제 클립보드와 저장 결과는 [실기기 확인](#도서-정보-이미지-내보내기-실기기-확인)에 남아 있습니다.
- TTS는 한 장짜리 TXT에서 마지막 문장으로 이동하고 종료하는 흐름과, 두 장짜리 EPUB에서 다음 장의 첫 문장으로 이어 듣는 흐름을 검증합니다. Chromium ZIP 웹툰의 관성 스크롤은 로컬에서 통과했고 CI 환경에서는 추가 확인이 필요합니다.
- 완료 조건은 전체 `browser-regression`과 Chromium/WebKit Playwright CI 통과입니다.

- 테스트 계정에서 기기 진행률 조회 실패 후 재시도하면 기존 위치에서 열리는지, 로그아웃 실패 후 같은 계정의 새 저장과 원격 수신이 다시 이어지는지 확인합니다.

- 완료 조건: 기존 오류 화면/상태 불일치가 재현되는지 판정하고, Drive 목록 복구·로컬 서재 보존·Firebase 상태 유지 결과를 기록합니다.

## 간헐적 EPUB 첫 페이지 열기의 실제 원인

- [1.8.37의 방어와 진단](updates/update_1.8.37.md#시작-위치-복원-검증과-경량-진단)은 좌표 없는 CFI/실제 이동 거부를 재현한 결과입니다. 특정 사용자 도서의 간헐적 원인은 미확정입니다.
- 재방문 조건: 문제가 다시 발생하면 통계 화면의 진단 JSON에서 `readerResumeFailures`를 확보하고 해당 도서·기기·저장 위치 조건으로 재현합니다. 정상 읽기 전체 로그를 상시 추가하지 않습니다.
- 2026-10-06 사용자 진단은 TXT 변환 EPUB 캐시를 두 번 열었으며, 두 번 모두 첫 장에서 `resume` 성공으로 끝났습니다. 원래/실제 진행률과 빌드·도서 구분 정보가 없어 이 파일만으로 저장 위치 덮임·복원 오류를 확정하거나 원래 위치를 복구할 수 없습니다. 재진입 후에도 0%라는 사용자 관측을 유지합니다.
- 코드 회귀에서는 사용자 이동 없는 첫 위치/레이아웃 relocate를 외부 강제 flush가 저장하는 경로를 재현·차단했습니다. 요청 진행률과 첫 위치가 불일치하는 성공 반환도 거부하며 대체 앵커를 사용합니다. 이 경로들이 사용자 증상의 실제 원인인지 실기기 확인은 아직 남았습니다. 다음 재발 시 `appBuild`, 요청/실제 진행률·해시를 포함하는 새 진단과 도서명·오류 전 진행률을 확보합니다.
- 2026-10-08 사용자는 아침·메모리 정리에 따른 종료 후 재실행과 연관 가능성을 제시했습니다. 인증 callback을 3초 이후로 늦추고 계정 복원을 보류하는 회귀에서, 게스트 자동 열기 후 로그인 계정 리더가 빈 진행률로 먼저 생성되는 순서를 재현·차단했습니다. 계정 복원 후 60%로 시작하는 자동 회귀는 통과했으나 실제 OS 메모리 종료나 사용자 기기의 발생 원인을 재현한 결과는 아닙니다. 새 진단의 `ownerHash`와 요청/실제 진행률을 대조하고 실제 기기 조건을 확보합니다.
- 계정 전환 전 리더의 종료 저장이 새로운 활성 owner의 저장 callback에 들어갈 수 있는 경로도 재현하고, 원래 owner/generation을 확인해 차단했습니다. 이번 수정의 실제 재실행·계정 전환 수용 확인도 함께 수행합니다.
- 완료 조건: 실제 trigger를 특정해 회귀로 검증하거나 확보한 제한적 증거와 아직 미확정인 범위를 명시합니다.

## 조건부 보류와 완료 근거 확인

- **Firestore 독서 통계 원본 등 보존:** event receipt는 위 [유한 동기화](#동기화-유효기간과-영수증-정리)로 분리했습니다. Firestore 통계 원본 등은 [1.8.9 보류 판정](updates/update_1.8.9.md#현재-보류-판정)과 [planStorageMaintenanceMigrationV1](../src/lib/storageMaintenanceDiagnostics.ts)의 관찰 조건을 유지하며 자동 삭제하지 않습니다.
- **카탈로그 delta compaction:** [1.8.15 보류·후속 버전](updates/update_1.8.15.md#보류후속-버전)의 별도 후속입니다. 재방문 조건은 요청형 delta가 크기 한도에 가까워질 때이며, 그때 Firestore on-demand 원본에서 base catalog를 재생성하는 별도 compaction release를 계획합니다. 후속 완료·폐기의 명시적 근거는 찾지 못해 조건부 보류로 보존합니다. 독서 데이터 Retention/compaction과 별개이며 즉시 구현할 작업으로 전환하지 않습니다.
- **NovelPia 인증 대상:** [1.8.15 Phase G](updates/update_1.8.15.md#phase-g--optional-auth-provider)의 코드는 완료되어 public-only 릴리스와 분리되어 있습니다. 실제 필요와 계정 설정이 생기면 CAPTCHA·성인 모드·session 검증과 secret 비노출을 별도 수용 확인합니다. 그 전에는 인증 대상 성공으로 판정하지 않습니다.
- **도서 정보 외부 리뷰 완료 근거:** [1.8.11의 대기 상태](updates/update_1.8.11.md)와 후속 전체 리뷰 기록을 대조해 이 gate의 완료/이관 근거를 확인합니다. 이번 문서 대조에서 기능에 연결된 명시적인 sign-off는 찾지 못했습니다. 완료 증거가 있으면 이 항목을 제거하고, 없다면 필요한 리뷰 범위를 확인해 남깁니다.
- **대형 파일 Worker·ready queue:** [1.7.8 보류 가이드](updates/update_1.7.8.md#보류-가이드)에 따라 실제 TXT/대량 이미지의 시간·메모리·취소 지연을 계측한 뒤 추가 Worker 이관을 재검토합니다. 현재 7z Worker나 Apple 모바일 ZIP 대체 경로를 미구현으로 취급하지 않습니다. 수천 건 outbox fixture에서 claim 비용이 문제가 될 때만 별도 ready queue를 검토합니다.
- **추가 진단 UI·복구 journal:** [1.7.9](updates/update_1.7.9.md#보류-가이드)의 추가 audit/진단 UI는 구체적 필요와 개인정보·보존 정책이 정해지면 재검토합니다. [1.7.6 리뷰 판정](updates/update_1.7.6.md#리뷰-판정)의 paused/dead-letter UI는 오류 분류 안정화, [1.8.12 보류 항목](updates/update_1.8.12.md)의 추가 충돌 계측은 리뷰/기기 증거가 조건입니다. iPad suspension이 IndexedDB commit을 끊는 증거가 있을 때만 일반 복구 journal을 검토합니다. 이미 구현된 통계 draft·경량 진단을 중복 구축하지 않습니다.
- **CSP 강제:** [1.7.8 보류 가이드](updates/update_1.7.8.md#보류-가이드)의 report-only 위반 수집, Google/Firebase/Drive/blob-worker 허용 경로 정리와 기기 확인을 먼저 수행해야 합니다. 호환성 근거 없이 CSP enforcement를 활성화하지 않습니다.
- **동기화 검증 환경·책갈피 깜빡임:** [1.8.13](updates/update_1.8.13.md#phase-f--observability와-multi-context-gate)의 격리 Auth/Firestore 다중 context 검증은 당시 emulator 세팅 부족으로 제한됐습니다. Rules emulator 통과와 구분해 해당 경로의 완료 근거/필요 설정을 확인합니다. 같은 문서의 별도 책갈피 optimistic overlay는 실제 기기에서 의미 있는 깜빡임이 확인될 때만 재검토합니다.
- **기타 사용 근거가 필요한 확장:** [1.8.14 보류·후속](updates/update_1.8.14.md#보류후속-버전)의 추가 태그/필터와 [1.7.7 리뷰 판정](updates/update_1.7.7.md#리뷰-판정)의 추가 삭제 saga/복구 확장은 구체적 사용·보존/내보내기 요구가 생길 때 원 계획과 최신 구현을 먼저 대조합니다. 확정된 미완료 구현으로 간주하지 않습니다.
