# 독서 통계

## 시간·날짜

화면 독서와 TTS 시간을 구분해 도서별·날짜별·기간별로 집계합니다. 단순히 책이 열린 시간 전체를 독서 시간으로 세지 않습니다. 화면 독서는 실제 활동·가시성·포커스·idle 경계를 적용하고 모바일 포커스 차이는 별도 정책으로 처리합니다. TTS는 실제 발화 구간을 사용하며 대기·일시정지·숨김·임시 이동을 읽은 시간으로 누적하지 않습니다.

화면 독서는 정상 전진 중 5분마다 확정하며 역행·명시적 탐색에서는 이동 전 구간을 먼저 닫습니다. TTS는 발화 구간을 1분 경계로 확정하고, 화면 독서와 TTS의 복구 초안은 5초 간격으로 보존합니다. owner/device/session 경계가 다른 draft를 덮거나, 저장 중 새 활동을 잃거나, 복구 때 같은 시간을 중복 집계하지 않아야 합니다. UTC 및 기기 시간 보정과 저장한 timezone offset으로 날짜 경계를 다룹니다. 집계는 기기별 시계 보정 표본을 시간순으로 정리해 각 세션의 시작과 가장 가까운 유효 표본을 찾습니다. 거리가 같으면 세션 ID의 UTF-8 순서에서 먼저 오는 표본을 써서 기기와 배치의 결과를 맞춥니다. 정확한 세션 상한/idle/checkpoint 기준은 [readingStatistics.ts](../../src/lib/readingStatistics.ts)가 담당합니다.

기간별 통계에는 집계 시간이 있는 도서를 파일당 한 줄로 표시하고 화면 독서와 TTS 시간을 구분합니다. 예전에 완료 처리한 기록의 실제 독서 시간도 합산합니다. 별도로 저장된 완료 마커는 시간을 늘리지 않습니다. 기존 기기에 저장된 회차 숨김 설정은 보존하며, 해당 회차의 독서 시간도 다시 표시합니다.

달력, 독서 시간 요약, 상세 통계와 내보낸 집계는 2분 이상인 독서 묶음만 합산합니다. 중복 시간과 날짜 경계를 처리한 뒤, 같은 날짜에 같은 도서·독서 방식·저장 시간대의 구간이 5분 이내로 이어지면 묶습니다. 휴식 시간은 합산에서 제외합니다. 달력은 묶음의 첫 집계 시각과 실제 독서 시간의 합을 표시합니다. 집계 구간에 세션 시작·종료 진행률이 두 개 이상 남아 있으면 최대값과 최소값의 차이도 %p로 표시합니다. 이 차이에는 건너뛴 구간이 포함될 수 있습니다.

마이페이지 달력과 통계 화면의 발행 집계는 `NEXT_PUBLIC_ENABLE_READING_STATS_ROLLUP_READS=1`에서 확인할 수 있습니다. 발행 범위는 읽은 기록이 없는 날짜까지 집계가 우선하며, 범위 앞과 뒤의 날짜는 로컬 세션으로 계산합니다. 첫 원본 수신 중에는 발행 집계를 먼저 표시합니다. 원본으로 발행 경계를 안전하게 잇기 전까지 확정 합계만 표시합니다. 발행본이 오래돼 최근 14일 수신 모드로 들어가도 검증된 날짜 합계는 표시합니다. 달력에서 독서 시간이 있는 날짜를 선택하면 해당 주 상세를 읽습니다. 통계 화면의 기간 합계는 날짜 집계를 사용하고, 도서별 기록은 선택 기간과 겹치는 주간 상세에서 계산합니다. 전체 기간은 누적 도서 합계를 사용합니다. 게스트나 발행 전 계정은 로컬 기록으로 계산합니다. 발행 범위의 누적 도서 합계나 미마감 원본 수신을 확인할 수 없으면 전체 기간 JSON 내보내기를 보류합니다.

같은 검증용 빌드에서 읽은책, 도서 상세, 리더와 도서 정보창의 독서 시간은 발행된 파일별 합계에 발행 범위 밖의 로컬 기록을 더합니다. 읽은책과 도서 상세는 파일에 기록된 제목 별칭으로 작품을 식별합니다. 도서 상세는 2%p 이상 연속해서 읽은 구간의 끝을 표시하며, 평가 증빙은 정지 중 읽은 기록까지 포함한 최대 진행률을 사용합니다. 파일별 집계를 사용할 수 없으면 로컬 원본으로 계산합니다.

## 저장·동기화·출력

세션은 계정별 IndexedDB에 보관하고 Firebase UID의 `readingStatsV1`으로 동기화합니다. 동기화 coordinator와 lease는 여러 탭의 같은 기록 처리 경합을 제어합니다. 실패한 전송은 기록을 없애지 않고 재시도 대상으로 남깁니다. 원본 수신이 중간에 실패하거나 리더십이 바뀌어도 이미 기기에 저장한 페이지가 있으면 열린 통계 화면에 변경을 알립니다. 화면이 닫힌 뒤 복귀, 오프라인, 계정 전환은 세션 소유권을 유지해야 합니다.

동기화 리더는 원격 첫 페이지를 먼저 반영하고, 다음 페이지가 있으면 페이지 사이에 대기 세션을 최대 4건 전송 시도합니다. 원격 반영이 끝난 뒤 남은 전송을 처리합니다. 페이지·원격 읽기 진단을 계속 기록하며 원격 반영 시간에는 페이지 사이의 전송 대기 시간을 합산하지 않습니다.

독서 기록은 서버에서 생성 후 불변입니다. 처음 받거나 복구할 때는 500건씩 읽고, 이후에는 마지막 서버 시각과 문서 ID 뒤에 추가된 기록을 받습니다. 영속 커서에는 실제 Firestore Timestamp를 사용합니다. 기존 커서는 해당 서버 문서의 ID와 나노초까지 일치하면 채택하고, 경계를 증명할 수 없으면 로컬 세션을 보존한 상태에서 다시 받습니다. 전체 검사에서 잘못된 타입은 격리하고 해당 실행에서 실제 쿼리 문서 위치 뒤로 진행합니다. 정상 증분 수신은 Timestamp 범위에 한정합니다.

7일 정기 검사에서는 마지막으로 받은 서버 시각·문서 ID까지의 원격 건수와 마지막 문서를 기기의 동기화 기록과 대조합니다. 기기에서 먼저 올린 기록 때문에 동기화 건수가 앞서면 기존 경계를 확인하고 정상 증분 한 페이지를 받아 건수와 경계를 다시 검증합니다. 격리 문서가 최대 8건이면 각 문서가 같은 범위에 있고 아직 손상 상태인지 확인합니다. 격리 문서의 복구·삭제, 범위 불일치, 누락, 검사 실패 시 전체 검사를 사용합니다. 동일 ID의 데이터 손상도 다시 확인할 수 있도록 마지막 전체 검사를 마친 뒤 28일이 지나면 전체 검사를 수행합니다. 검사 중 앱을 닫으면 마지막으로 반영한 Timestamp 경계에서 이어가며, 커밋되지 않은 손상 구간은 다시 읽을 수 있습니다. 원격에서 사라진 기록의 자동 삭제나 업로드 시각 필드가 없는 기록까지 포함하는 감사에는 별도 복구 정책이 필요합니다.

로그인한 계정에 서버 독서 세션이 생기면 [정기 배치](../operations/deployment-and-recovery.md#공유-예산과-정기-마감)가 계정을 찾아 첫 집계를 준비합니다. 집계 조회를 켠 기기는 발행 달력이 이력 시작을 덮고 도서별 합계와 마감 시점의 입력을 함께 검증하면 집계 수신으로 전환합니다. 새 발행본과 마감 시점의 입력을 적용할 때 기존 동기화 완료 원본을 로컬에서 교체하고, 해당 마감 이후의 정상 업로드를 증분으로 다시 받습니다. 기기의 미전송 기록은 보존합니다. 확정 주의 시간 배분을 바꾸는 기록과 서버에서 형식 오류로 격리한 기록은 합계에서 제외합니다. Firestore 원본은 보존합니다. 기기에 저장한 발행 합계는 오프라인에서도 표시합니다.

집계 수신은 정확한 마감 Timestamp 뒤의 업로드만 조회합니다. 늦은 기록을 우선 실제 시계 보정과 겹침 배분으로 평가합니다. 지난주 마감 뒤에 올라온 월요일 기록도 확정 구간을 그대로 유지하면 해당 미마감 주에 반영합니다. 이미 확정된 날짜의 시작 시각이나 시간 배분이 바뀌는 기록은 합계에서 제외합니다. 클라이언트 수신, 정기 마감, 평가 증빙은 같은 판정을 사용합니다. 건너뛴 문서도 수신 위치에 반영하며 첫 조회가 비어 있으면 마감 Timestamp를 유지합니다. 그 뒤에는 마지막으로 확인한 문서의 Timestamp와 ID부터 이어갑니다. 기기는 화요일 오후 6시 KST 이후 온라인 상태에서 집계 발행을 확인하고 발행이 늦어지면 한 시간 간격으로 재확인합니다. 통계 진입과 수동 새로고침에서도 확인합니다. 서버는 설치본과 발행 범위 및 마감 Timestamp가 일치하면 발행 포인터만 조회합니다.

유효한 집계와 기존 원본 커서를 모두 사용할 수 없으면 최근 14일의 `uploadedAtServer`부터 원본을 받습니다. 복구 상태에서는 별도 로컬 커서를 유지하며 일부만 받은 기록을 전체 이력으로 확정하지 않습니다. 발행 집계 이후에 올라온 손상 문서는 진단에 기록하고 해당 문서 위치까지 커서를 옮깁니다. 유효한 집계와 나머지 기록은 계속 표시합니다. 이전 버전이 보류한 발행본도 다시 적용할 수 있습니다. 달력은 화면을 열 때 기기에 보관한 집계를 확인하고, 화면이 열린 동안에는 로컬 통계 변경 알림으로 갱신합니다. 개별 주 상세를 불러오지 못하면 발행된 날짜 합계를 그대로 표시하고 해당 날짜에 상세 조회 실패를 표시합니다.

원본 전체를 받은 기기는 최근 커서와 원격 건수·마지막 문서 대조가 일치하면 계속 증분만 받습니다. 28일이 지나도 앱에서 과거 원본 전체를 자동 검사하지 않으며, 대조 실패 시 최근 복구를 사용합니다. 관리자 원본 수정·복원 시에는 [운영 가이드](../operations/deployment-and-recovery.md#공유-예산과-정기-마감)에 따라 집계를 다시 만듭니다.

보이는 탭의 자동 수신은 평소 1분 간격이며, 받은 기록이 없는 체크가 이어지면 2분, 5분, 10분으로 간격을 늘립니다. 새 기록을 받으면 같은 계정의 다른 탭에도 결과를 알려 1분 간격으로 돌아갑니다. 짧은 화면 복귀와 토큰 갱신은 마지막 성공한 서버 확인 뒤 1분 동안 추가 자동 수신을 생략합니다. 마이페이지 달력이나 통계 화면을 열거나 수동 새로고침을 누르거나 다시 온라인이 되면 즉시 수신을 요청합니다. 로컬 변경에 따른 전송은 자동 수신 간격과 별도로 처리합니다.

평가가 재전송되었거나 버전이 충돌하거나 기존 증빙을 계속 쓸 수 있으면 서버 독서 이력을 읽기 전에 확인합니다. 기기가 원본 전체를 받은 경우에만 동기화된 로컬 세션에서 증빙을 보냅니다. 서버 증빙이 필요하면 조회를 마친 뒤 항목·별칭·버전을 다시 검증합니다. 집계 조회를 켠 빌드는 시작 범위가 확인된 파일별 발행 합계에 열린 기간과 발행 커서 뒤에 올라온 세션을 합쳐 증빙을 계산합니다. 마감된 날짜의 기기 시계 보정과 겹침 배분은 발행 시점의 값을 씁니다. 집계나 증분을 검증할 수 없거나 증분이 한도를 넘으면 별점·한줄평을 증빙 없이 저장하며 기존 증빙은 보존합니다.

집계 조회를 끈 환경의 서버 평가 증빙은 원본 이력과 파일별 계산 결과를 별도 한도로 같은 인스턴스에 보관합니다. 최신 업로드와 총 건수가 같으면 파일별 결과를 재사용하고 별칭은 다시 확인합니다. 원본과 새 기록의 건수가 맞으면 증분을 합쳐 전체 기기의 시간 배분을 다시 계산합니다. 첫 요청이나 캐시·검증 조건을 충족하지 못한 요청 등에는 업로드 시각이 없는 이전 기록까지 읽습니다.

통계 화면 헤더에는 JSON 저장·공유·진단·새로고침 아이콘을 이 순서로 제공합니다. 저장과 공유는 전체 기간의 합계와 날짜별·도서별 합계를 담은 `schemaVersion: 2` JSON을 사용합니다. 집계와 이후 기록을 모두 받으면 전체 기간을 저장할 수 있습니다. 최근 복구 상태에서는 달력과 통계에 확인된 기록을 표시하며 전체 JSON 저장·공유는 집계 복구까지 비활성화합니다. 공유 미지원 시에도 같은 JSON을 저장합니다. 독서 인증 이미지는 도서 정보창에서 제공합니다. 출력 파일의 계약은 `readingStatisticsExport`와 delivery 코드가 담당합니다.

## 진단

진단은 중단된 동기화 작업의 대상 종류와 오류 코드별 건수, 설치된 통계 집계의 날짜 범위, 최근 14일 복구 여부를 표시합니다. 이전 버전의 집계 거절 시각이 기기에 남아 있으면 함께 표시합니다.

통계 화면의 **진단**은 저장소/동기화 요약 JSON을 내보냅니다. 본문과 메모를 넣지 않습니다. 시작 위치 복원 거부가 발생한 열기만 최근 8건, 직렬화 크기 제한 안에서 `readerResumeFailures`로 보관·출력합니다. 결과·시도 횟수·해시화한 목표·페이지/좌표 유무·화면 크기만 기록하고 원본 CFI·도서 ID·제목은 남기지 않습니다. 정상 열기는 이 실패 기록을 쓰지 않습니다.

진단의 `appBuild`는 앱 버전과 빌드 식별자입니다. 열기 성능 버퍼에는 해시화한 도서·소유자·목표·앵커, 요청 진행률과 실제 열린 진행률·페이지를 포함합니다. `ownerHash`로 같은 도서가 게스트와 로그인 계정에서 연속으로 열린 경우를 구분하며 UID 원문은 넣지 않습니다. 진행률 불일치로 거부된 복원은 `readerResumeFailures`의 `progress-mismatch` 사유와 요청·최종 실제 진행률로 남깁니다. 정상 열기마다 영구 기록을 추가하지 않습니다.

Bootstrap 추적은 `?readerDebug=1` 또는 `reader_bootstrap_trace_v1` 설정으로 켜는 제한된 메모리 버퍼입니다. 열기 성능 추적(`readerOpenPerformanceTrace`)은 느린 cold-open 재현을 위해 debug 설정 없이 제한된 메모리 버퍼에 유지합니다. phase·시간·개수·크기와 해시화된 목표만 기록하며 본문·제목·원본 CFI는 넣지 않습니다. 실패 기록과 항상 실행되는 전체 로그를 혼동하지 않습니다. 진단에서 오래된 receipt/tombstone/이전 namespace가 보이더라도 삭제 가능하다는 뜻은 아닙니다. 정리 승인 조건은 [운영 가이드](../operations/deployment-and-recovery.md#저장과-복구)에 있습니다.

`readerBootstrapTrace`의 `reading-statistics-hydration`은 원격 수신 한 번에 대해 시작 커서 유무, 문서 반환 쿼리의 시도·완료·빈 응답 횟수, 반환 문서 수, 건수 대조 결과(`auditProbe`)와 집계 범위 확인 결과(`publishedAudit`)를 기록합니다. `publishedBootstrap`으로 집계 첫 수신, 이후 수신, 원본 복구를 구분합니다. 저장소 요약의 `remoteReadCount`는 완료한 문서 반환 쿼리 횟수입니다. 주간 검사의 집계 쿼리 비용은 Firestore 사용량과 대조합니다. `fullScanReason`으로 신규·빈 이력, 로컬 누락·건수 차이·격리, 정기 전체 검사, 원격 대조 불일치·실패 등을 구분합니다. 같은 기기의 전송 확인이 수신 커서보다 앞서면 `local-synced-count-ahead`로 기록될 수 있습니다.

진행률은 `listener-reconciled`의 `wakeReason`으로 재시작 원인을 확인하고, 리스너를 붙인 뒤 첫 `authoritative-snapshot`의 `durationMs`와 `snapshotDocuments`로 준비 시간과 결과 크기를 봅니다. 스냅샷 문서 수는 Firestore에서 과금한 읽기 수와 다를 수 있습니다. 화면 복귀 시 열린 책의 단건 조회는 `active-progress-refresh`에 기록합니다. `write-lease-issuance`에는 실제 발급 시도의 사유·결과·시간이 남습니다. 같은 실행에서 이미 확인한 권한을 재사용하거나 진행 중인 발급에 합류한 경우에는 발급 이벤트가 생기지 않습니다. 실기기에서는 같은 계정으로 앱 재실행과 네트워크 복귀를 각각 재현한 직후 진단 JSON을 저장해 비교합니다.
