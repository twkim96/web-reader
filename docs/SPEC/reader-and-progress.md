# 리더와 진행률

## 읽기와 시작 위치

`EpubReader`는 EPUB/TXT·PDF·이미지 압축 도서의 공통 화면입니다. EPUB/TXT에는 페이지·스크롤 이동, 목차·본문 검색·CFI/% 이동과 본문 스타일을 제공합니다. PDF와 이미지 압축 도서는 고정 레이아웃 경로를 사용하며 텍스트 선택·주석·TTS를 활성화하지 않습니다. 고정 레이아웃 확대·이동 제스처의 시각 계약은 [화면 사양](interface.md)에 있습니다.

저장된 위치를 여는 것만으로 진행률이나 `lastRead`를 갱신하지 않습니다. EPUB CFI 이동은 목표 좌표와 실제 도달 여부를 확인해야 합니다. 좌표가 없는 목표나 존재하지 않는 CFI 범위를 첫 페이지의 성공으로 바꾸지 않습니다. 로딩 중에 저장 위치·대체 앵커를 최대 두 차례 순회하고 복원에 실패하면 오류를 알린 뒤 서재로 돌아갑니다. 읽기를 시작한 후 지연된 재시도로 사용자를 이동시키지 않습니다.

리더는 활성 계정의 로컬 진행률 복원이 끝난 뒤에만 생성합니다. 느린 인증으로 임시 게스트 서재가 먼저 열렸더라도 로그인 계정으로 전환해 진행률을 읽는 동안에는 로딩 화면을 표시합니다. 복원 전의 빈 CFI를 리더 시작 위치로 고정하지 않습니다. 이 준비 조건은 첫 자동 열기와 계정 전환 뒤 이미 열려 있던 도서의 재생성 모두에 적용합니다.

저장 진행률이 5% 이상인데 복원 직후 실제 진행률이 0.1% 이하라면, 엔진이 이동 성공을 반환해도 복원 거부로 처리하고 같은 대체 앵커·재시도 경로를 사용합니다. 정상적인 첫 위치 저장·열기는 허용합니다. CFI와 진행률이 이미 함께 0%로 덮인 기록은 이 검사만으로 복구할 수 없습니다.

재현한 렌더러 실패 경로에 대한 방어가 구현되어 있지만 실제 사용자 도서의 간헐적 첫 페이지 열기 원인은 아직 확정하지 않았습니다. 재발 시 필요한 최소 기록은 [진단](reading-statistics.md#진단)에 있습니다.

## 압축 이미지 웹툰 모드

ZIP/CBZ/7z 이미지 압축 도서의 웹툰 모드는 이미지 블록을 가로 폭에 맞춰 원래 비율로 표시하고 끊김 없이 세로로 스크롤합니다. 짧은 이미지가 연속되어도 페이지 넘김 없이 같은 스크롤로 지나갑니다. 설정 `archiveWebtoonMode`는 기기에 별도로 저장하며 기본값은 꺼짐이고 불리언 `true`만 켜짐으로 읽습니다. 기존 `navMode`와 PDF·EPUB/TXT·일반 탭 모드는 바꾸지 않습니다. 토글 위치는 [화면 사양](interface.md#메뉴모달모바일)에 있습니다.

웹툰 모드는 화면 크기의 sandbox iframe 내부에서 일반 터치와 휠을 네이티브 스크롤로 처리하며 전체 화면 interaction overlay를 사용하지 않습니다. 핀치 확대, 지정된 modifier 드래그와 마우스 pan은 웹툰 전용 명시적 제스처로 유지합니다. 일반 스크롤의 진행률 입력 감지는 passive이며 명시적 확대 제스처만 기본 동작을 차단합니다. 텍스트·PDF·일반 고정 레이아웃의 탭 경로는 그대로 유지합니다. 변하지 않은 크기와 DOM 순서는 다시 배치하지 않습니다. 화면 밖 공간은 높이만 남겨 선행 로딩 창이 이동해도 스크롤 좌표를 재설정하지 않으며 네이티브 관성을 유지합니다. 실제 iPad/PWA의 120Hz 화면에서 체감 지연과 스크롤 품질은 별도 수용 확인 대상입니다.

진행 위치는 화면 위쪽에 걸린 이미지의 페이지 번호이며 책 맨 아래에서는 마지막 페이지입니다. 이미지 인덱스가 바뀔 때만 기존 relocate 이벤트를 `fraction: 0`, `size: 1`로 보냅니다. 선행 로딩·크기 변경·모드 레이아웃만으로 사용자 이동을 만들어 내지 않습니다. 기존 페이지 CFI로 다시 열거나 이동하면 해당 이미지의 맨 위에서 시작하며 이미지 내부 오프셋은 저장하지 않습니다. 저장·동기화 코드나 스키마는 변경하지 않습니다.

렌더러는 하나의 sandbox iframe 안에서 이미지 블록을 구성하고 현재 이미지 기준 앞뒤 5장을 기본 Blob 창으로 유지하며, 짧은 이미지가 여러 장 보이면 화면을 채우도록 최대 64장까지 확장합니다. 동시 로딩은 최대 두 개입니다. 실제 디코딩은 화면과 양쪽 이웃 이미지 한 장씩으로 제한하며, 헤더에서 크기를 알 수 없는 이미지는 표시될 때 브라우저의 `naturalWidth`/`naturalHeight`로 크기를 확인합니다. 실제 iPad/PWA 수용 확인은 [TODO](../TODO.md#압축-이미지-웹툰-모드-실기기-확인)에 있습니다.

## 자동 두 페이지

EPUB/TXT의 좌/우·상/하 여백은 각각 기기 설정 `horizontalMarginStep`·`verticalMarginStep`에 1~7 단계로 저장하며 기본은 4입니다. 기존 설정에 값이 없으면 4로 복원하고 범위 밖 숫자는 1~7로 제한하며 잘못된 타입은 4를 사용합니다. 진행률·동기화 스키마는 바꾸지 않습니다.

가로쓰기 본문의 좌우 바깥 여백은 단계 1~7에 한쪽 2~8%를 대응시킵니다. 기본 4단계는 기존 5%입니다. 비율을 `r`이라 할 때 폭 400px까지 `폭 × r`, 이후에는 `400px × r + (폭 − 400px) × r × 0.7`을 적용합니다. 같은 폭의 한 페이지와 두 페이지는 같은 바깥 여백을 사용하고, 두 페이지 중앙 간격은 기존 5% 기반 계산을 유지합니다. 본문 최대 폭에 도달하면 중앙 정렬에 필요한 바깥 공백이 추가될 수 있습니다. 스크롤 모드에도 선택한 바깥 여백을 적용합니다. `outside-margin` 속성이 변경되면 현재 읽던 내용을 유지하며 즉시 다시 배치하고, 속성이 없는 Foliate 사용자는 기존 gap 기반 비율을 사용합니다. 탭 모드는 문서의 좌우 패딩을 중앙 간격의 절반으로 유지해 열 이동 폭과 페이지 이동 폭을 일치시킵니다. 선택 여백이 그보다 작으면 페이지 표시 영역을 양쪽으로 넓혀 바깥 여백만 줄입니다. 1/7도 허용하며 옆 페이지 조각을 노출하는 최소 여백 제한은 두지 않습니다. 세로쓰기의 좌우 축과 PDF·이미지 고정 레이아웃은 기존 배치를 유지합니다.

텍스트의 상하 바깥 여백은 각각 기존 `max(설정 padding, 글자 크기)`에 `(단계 − 4) × 4px`를 더합니다. 기본 padding 24px·글자 크기 20px에서는 단계별로 12·16·20·24·28·32·36px입니다. 글자 크기나 기존 padding이 더 크면 그 값을 기준으로 조절합니다. 본문 내부의 별도 패딩은 유지하며, PDF·이미지에는 새 여백 단계를 적용하지 않습니다.

EPUB/TXT에서 `자동 2페이지 보기`를 켜면 탭 이동 모드의 리더 영역이 가로 ≥ 세로(1:1 이상)일 때 두 페이지, 가로 < 세로일 때 한 페이지를 표시합니다. 정사각형도 두 페이지에 포함하며 최소 너비나 1,000px 초과 조건은 두지 않습니다. 접기·펼치기·회전·창 크기 변경은 현재 본문 위치를 유지하면서 다시 분할합니다. 옵션을 끄거나 스크롤 모드를 사용하면 한 페이지입니다. PDF·이미지 도서는 이 옵션의 대상이 아닙니다.

기존 기기 설정 키 `landscapeTwoPage`는 그대로 사용합니다. 비율 경계는 [view-policy.js](../../public/foliate-js/view-policy.js)를 렌더러와 메뉴가 공유합니다. 본문의 `max-inline-size`는 페이지 너비 상한이며 두 페이지 활성화 조건이 아닙니다. 세로쓰기 도서는 글 진행 축에 맞춰 가로·세로 기준을 바꿉니다.

## 저장·책갈피

실제 사용자 이동 후 유한한 진행률만 저장합니다. 일반 페이지/스크롤 이동은 멈춘 뒤 저장하고 연속 이동에도 저장 간격 상한을 둡니다. 명시적 이동은 이동 후 위치가 안정화된 뒤 저장하며, 화면 숨김·종료는 남은 일반 저장을 flush합니다. 정확한 타이밍 값은 `useReaderProgressSave`의 상수를 기준으로 합니다.

외부 flush와 현재 위치의 강제 저장도 미저장 사용자 이동이 있어야 기록합니다. 저장할 변경이 없으면 flush는 성공으로 반환하되 복원·레이아웃 변경으로 관측된 위치를 저장하지 않습니다. 임시 이동 확인은 별도의 명시적 확정 경로이며 이 제한 때문에 차단하지 않습니다.

저장 직전에 리더 생성 당시의 owner와 generation이 여전히 활성인지 확인합니다. 계정 전환 후 이전 리더의 종료 저장·대기 저장이 새 계정 진행률에 들어가지 않아야 하며, 같은 계정으로 돌아와도 이전 generation의 저장 요청은 되살리지 않습니다.

목차·검색·책갈피·CFI/% 이동은 **이동 후 위치**를 최신 진행률로 사용합니다. 이동 전 위치는 필요할 때 로컬 자동 책갈피에만 남깁니다. 수동 책갈피는 Firebase 계정으로 동기화하고 자동 책갈피는 기기 로컬 기록으로 유지합니다. 원격 수동 책갈피 갱신은 로컬 자동 책갈피를 지우지 않습니다.

## 진행률 슬라이더의 임시 이동

드래그 중에는 독립 소스로 본문/페이지 미리보기를 추출합니다. EPUB/TXT는 장 내부 문자 비율을 사용하므로 실제 페이지 첫 문장과 정확히 같지는 않습니다. PDF·압축 도서는 페이지 이미지를 보여 줍니다. 추출 요청은 지연·직렬 실행·취소와 URL 해제로 오래된 결과와 자원 누적을 막습니다.

슬라이더를 놓으면 본문은 선택 위치로 이동하고 확인 패널을 표시합니다. 확인 전에는 새 위치를 저장·동기화하지 않으며, 자동/강제/종료 저장과 외부 flush·원격 위치 채택을 막습니다. 다른 리더 메뉴 이동도 같은 임시 세션에서 직렬로 처리합니다. 여러 번 움직여도 최초 출발 위치를 유지합니다.

- 확인: 실제 임시 위치 저장에 성공한 뒤 임시 상태를 종료합니다. 최초 출발 위치와 5%p를 초과해 달라졌다면 출발 위치의 자동 책갈피를 남깁니다.
- 취소: 최초 CFI/진행률 복원에 성공한 뒤 임시 상태를 종료하고 기존 대기 저장을 복구합니다.
- 실패: 재시도할 수 있게 임시 상태와 오류를 유지합니다. 수동 책갈피 편집은 독립적으로 보존합니다.

확인 패널은 바깥 클릭으로 닫히지 않는 비모달 안내이며 배경 메뉴·키보드 포커스를 가두지 않습니다. 진행바의 정밀 입력은 `ReaderToolbar`의 pointer layer가 담당하며 수직 감도 전환 중 위치가 튀지 않아야 합니다.

## 동기화와 충돌

열린 책이 있는 상태에서 화면으로 돌아오면 서버에 그 책의 진행률을 확인합니다. 15초 이내 복귀하고 같은 계정 리스너가 숨기기 전과 숨겨진 동안의 서버 스냅샷을 모두 처리했으면 단건 조회를 생략합니다. 리스너가 다시 붙었거나 연결이 불확실하면 단건 조회를 사용합니다. 리스너 복구는 현재 연결이 처리한 첫 서버 응답을 기준으로 판단합니다. 정상 연결이 조용히 유지되는 동안은 이 조건으로 재연결하지 않습니다.

진행 상태의 소유자는 Firebase UID입니다. Drive 연결·해제·계정 교체는 진행률 listener/outbox/conflict를 바꾸지 않습니다. 저장 이벤트는 IndexedDB outbox를 거쳐 Firestore revision 비교와 event receipt가 있는 transaction으로 적용됩니다. 같은 이벤트 재시도는 중복 적용하지 않고 초기화·삭제는 tombstone으로 표현합니다.

읽기 시작 뒤 도착한 다른 기기의 위치는 리더의 클라우드 동기화 창에 저장된 진행률을 표시하고 ‘이동하기’와 ‘무시’로 묻습니다. 사용자가 위치를 조작하지 않은 첫 복원에서는 자동 이동할 수 있으며, 자동 이동이 로컬 조작이나 저장 때문에 중단되면 비모달 이동 안내를 남깁니다. outbox에서 서로 다른 두 위치가 경합하면 ‘이어 읽을 위치 선택’ 배지를 표시하고, 배지를 열면 두 위치를 비교할 수 있습니다. 두 기록의 기기 ID가 같으면 상대 위치를 ‘이 기기의 이전 저장’으로 표시합니다. 동등한 anchor 위치는 조용히 정리합니다. 원격 위치를 선택하면 실제 이동과 revision 검증을 거쳐 그 위치를 이어받습니다.

자동 이동을 중단한 뒤 책을 다시 열면 현재 서버 위치와 일치하는 미해결 이동 안내를 복원합니다. 알림을 닫았거나 자동으로 사라진 경우에는 책갈피 패널의 이동 항목만 유지하고, 이미 채택했거나 무시한 위치는 표시하지 않습니다. 최신 서버 버전의 읽기 위치가 다르면 표시된 퍼센트가 같을 정도로 이동 폭이 작아도 일반 확인창에서 이동 여부를 묻습니다.

열린 일반 클라우드 위치 확인창은 같은 도서의 더 높은 revision이 들어오면 이동 대상을 갱신합니다. 기존 이동·무시 요청의 늦은 결과가 새 확인창을 닫거나 오류를 덮어쓰지 않습니다. guard 해제도 동일 도서·현재 target·attempt에만 적용합니다. 최신 target을 명시적으로 무시하면 그보다 오래된 이동 실패 guard도 해제하지만, 새 guard나 새 이동 시도가 생긴 뒤의 늦은 완료는 거부합니다. 서버 채택 뒤 화면 이동이 실패하면 같은 revision에도 재시도와 현재 위치 유지 선택을 남깁니다. 명시적 충돌 해결 명령과 사용자가 닫은 창은 이 자동 갱신과 구분합니다.

수신한 최신 head와 화면이 실제 채택한 revision을 구분합니다. 새 진행률 쓰기는 채택한 위치 또는 명시적으로 무시한 원격 revision을 기준으로 하며, 수신만 한 최신 revision을 빌려 과거 화면을 덮어쓰지 않습니다. 책장의 진행률 초기화와 도서 삭제에 따른 초기화도 실행 시점에 기기가 채택했거나 명시적으로 무시한 revision을 기준으로 삼습니다. reader마다 별도 viewport ID와 채택 기준을 고정하고, 공유 IDB 행이나 다른 viewport의 대기 이벤트를 인과 기준으로 승계하지 않습니다. 같은 viewport의 실제 ACK만 후속 기준을 갱신합니다. 진행률 숫자·시간·다른 기기·비활성 도서라는 이유만으로 서로 다른 위치의 자동 승자를 정하지 않습니다. ACK 응답 유실 후 재전송은 해당 receipt의 실제 수락 revision을 사용합니다. 서버 위치 채택 후 화면 이동이 실패하면 이동 성공 또는 명시적 무시 전까지 이전 화면의 자동/종료 저장을 차단합니다.

종료 전 저장을 복원하는 것만으로 새 쓰기를 만들지 않습니다. 복원한 위치가 이 기기의 대기 이벤트와 정확히 일치하면, 이후 실제 이동은 아직 제출되지 않은 마지막 저장에 합칠 수 있습니다. 이미 제출했다면 해당 저장의 receipt가 증명한 revision으로 후속 쓰기를 보냅니다. 그 사이 서버에 다른 위치가 저장되거나, 복원한 위치에 대응하는 증거가 사라졌다면 위치 선택으로 넘어갑니다. 증명에는 위치 기록마다 다른 로컬 토큰을 사용하며 뒤로 읽기도 같은 규칙을 따릅니다. ‘이 기기에서 계속 읽기’를 누르면 화면에 표시한 두 위치가 유효한지 다시 확인한 후, 현재 도서의 리더를 선택한 위치에서 다시 엽니다.

책장에서 읽은 내역만 초기화하면 직접 추가한 책갈피는 보존합니다. 도서 전체 삭제에는 기존 책갈피 삭제 흐름이 포함됩니다. 두 초기화 모두 같은 탭에서 먼저 요청한 저장이 기기에 기록되기를 기다립니다. 위치 토큰이 일치하면 그 저장의 실제 서버 수락 버전을 기준에 반영합니다. 초기화를 요청한 뒤 받아들인 원격 위치나 다른 탭·기기의 저장은 그대로 충돌 비교 대상입니다.

### 유한 동기화

Vercel 운영 빌드는 쓰기 권한을 기본 활성화합니다. Firestore Rules는 모든 계정의 진행률·책갈피·주석·팔레트 동기화에 유효한 서버 발급 쓰기 권한을 요구합니다. 기존 기록은 최신 앱에서 읽을 수 있습니다. 차단 전환 시각과 다음 운영 단계는 [복구 가이드](../operations/deployment-and-recovery.md#유한-동기화와-영수증-정리)에 있습니다. 대안·실계정 읽기 전용 집계는 [검토 근거](../design/finite-sync-retention.md)를 참조합니다.

- 새 이벤트 ID에 불변 서버 발급 lease ID·발급 시각·UUID를 고정합니다. 진행률·책갈피·주석·팔레트의 서버 쓰기는 해당 기기의 발급부터 90일까지만 허용합니다. 기존 lease 문서의 수정/삭제는 금지하고 정책 문서는 관리자만 변경합니다. 클라이언트 시각은 권한 증거가 아닙니다.
- 온라인 새 작업은 24시간 이상 된 lease 대신 새 권한을 준비합니다. 이미 만든 이벤트는 retry·coalescing·인증 복구에서 권한을 갱신하지 않습니다. 충돌의 로컬 유지 대체 이벤트도 원래 lease를 유지합니다. 서버가 확인한 발급 시각과 단조 시계로 만료를 판단하며 기기 벽시계 오차를 만료로 취급하지 않습니다. 한 번 제출한 payload는 원래 ID로 보존하고 후속 수정은 별도 이벤트로 만듭니다.
- 미발급 placeholder는 생성 실행이 Web Lock을 잡은 뒤 그 실행 ID와 함께 저장합니다. lock이 유지되는 동안 다른 탭은 해당 작업의 claim과 만료를 건너뛰며 다른 대상은 계속 동기화합니다. 서버 시각과 쓰기 권한을 확인한 생성 실행만 자기 미제출 이벤트를 원자적으로 한 번 연결합니다. 잠금 해제가 확인되면 원래 이벤트와 payload를 `expired`로 보존하고 최신 서버 상태를 복구합니다. 추적 ID의 lock 상태를 확인할 수 없으면 작업을 그대로 유지합니다. 기존 legacy ID는 신뢰 서버 시각으로 확인한 뒤 원래 복구 경로를 따릅니다.
- Web Locks를 확보하지 못한 새 작업은 미추적 ID로 저장합니다. 생성 실행은 메모리에서 자기 작업을 식별해 복구에서 제외하고 온라인 복귀 후 연결합니다. 재실행 또는 다른 탭에서는 생성 탭의 생존 여부를 확인할 수 없으므로, 신뢰 서버 시각을 확보하면 legacy ID와 같이 원래 이벤트와 payload를 보존하고 최신 서버 상태를 복구합니다. 다른 탭이 먼저 복구하면 생성 탭에서 살아 있는 미추적 작업도 연결되지 않습니다. 탭 간 생존 보호는 추적 ID에 적용합니다.
- 진행률은 서버 시각을 확인하기 전에도 같은 기기·실행·뷰포트에서 만든 미제출 마지막 저장을 병합할 수 있습니다. 해당 실행이 만든 연결 전 placeholder 또는 현재 캐시와 같은 원래 lease만 병합하며 이벤트 ID, 기준 revision, 선행 위치 토큰을 유지합니다. 재실행에서 복원한 위치 토큰을 근거로 한 병합은 신뢰 서버 시각으로 lease를 확인한 경우에만 허용합니다.
- 만료 선행 작업과 유효 후속 작업을 분리하고, 유효한 후속 의도는 canonical 상태와 비교할 명시적 충돌로 보존합니다. pending 외에 conflict·blocked·deferred도 만료 복구 대상으로 찾습니다. 대상의 최신 서버 상태를 받은 뒤 새 편집을 허용하며 수신 실패 시 복구 대기를 유지합니다. 게스트·기기 도서 파일은 이 정책의 대상이 아닙니다.
- 책 전체 주석 삭제 intent에도 원래 권한과 기기를 고정합니다. 권한 필드 없는 legacy intent와 재연결할 수 없는 복원 intent는 신뢰 서버 시각을 확보한 뒤 최신 상태 복구 대상으로 찾습니다. 현재 실행의 미제출 pending intent는 바인딩을 기다립니다. 만료 후 최신 주석과 삭제 marker를 원자적으로 다시 받고 intent는 보존한 채 재실행을 막습니다. 서버 수신 중 새 작업·계정 변경·더 최신 cache가 발견되면 채택하지 않습니다.
- 만료된 책갈피를 복구할 때는 그 책갈피만 갱신하고, 열려 있는 리더와 페이지 저장을 유지합니다. 원격에서 지운 책갈피를 명시적으로 ‘이 기기 유지’로 복원하면 새 ID를 사용해 이후 편집·삭제를 이어갑니다. 복구 대기 중인 기록은 최신 서버 기록을 다시 받는 중으로 표시합니다.
- IndexedDB v16은 기존 outbox store를 데이터와 인덱스를 보존해 이름만 바꿉니다. 구버전 worker와 새 위치 복원 규칙이 섞이지 않도록 같은 프로필의 구버전 DB 연결을 차단합니다.
- 정리 API는 receipt 생성 후 120일과 검증된 legacy 차단 정책 이후 120일을 모두 요구합니다. head·revision·tombstone·도서 삭제 marker는 지우지 않습니다. 서버 정리 플래그도 별도로 기본 꺼짐이며 상세 운영 계약은 [복구 가이드](../operations/deployment-and-recovery.md#유한-동기화와-영수증-정리)에 있습니다.
