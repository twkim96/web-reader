# 다른 프로젝트에 전달할 프롬프트

아래 내용을 대상 프로젝트의 AI 또는 개발자에게 전달하세요. `ui-kit/`의 실제 위치만 수정하면 됩니다.

---

이 프로젝트의 UI 디자인을 첨부된 `ui-kit/`의 Web Reader 테마로 통일해 주세요.

먼저 `ui-kit/README.md`, `tokens.css`, `components.css`, `COVERAGE.md`를 읽고, `index.html`에서 테마·재질·질감과 모달을 확인하세요. 카탈로그 화면 자체의 대형 제목이나 전시 배치를 제품 화면으로 복제하지 말고, 공통 재질과 요소 규칙을 적용해 주세요.

기본 조합은 별도 지정이 없으면 `midnight + standard + none`으로 시작하세요. 테마, 포인트색, 재질, 질감은 서로 독립적으로 취급합니다. 제품에 테마 선택기가 있다면 모든 표면에 선택값이 전파되게 해 주세요.

원래 프로젝트의 API, 데이터 구조, 라우트, 주 동작과 사용자 흐름은 유지하세요. Web Reader의 책장/리더/동기화 기능을 새로 추가할 필요는 없습니다. 현재 프로젝트에 있는 화면과 동작을 이 키트의 레시피에 연결해 주세요.

착수 시 전체 화면과 모달의 진입점을 찾아 `대상 화면 | 키트 레시피 | 상태 | 확인 결과` 표를 만들고, 다음 범위를 확인해 주세요.

- 배경, 헤더, 내비게이션, 도크, 카드, 목록과 상세 화면.
- 설정, 테마 선택, 검색, 필터, 편집, 업로드처럼 넓은 모달.
- 삭제/로그아웃/진행 확인, 충돌 해결, 메모/번역, 설치/로그인 고지처럼 작은 모달.
- 아이콘 버튼, 상태바, `#` 같은 작은 진입점, 길게 누르기, 우클릭, 텍스트 선택으로만 나타나는 메뉴와 팝오버.
- 기본/hover/pressed/focus-visible/disabled/loading/error/empty/success 상태와 안내 배너·토스트.
- 모바일 배치, 긴 제목, 긴 모달 본문, 키보드 표시, safe-area, 가로 화면.

대상에 없는 기능은 `해당 없음`으로 기록합니다. 이미 있는 기능에 대응하는 표면이 빠지지 않도록 작업 중 이 표를 갱신하세요.

재질을 패널 배경 한 곳에만 적용하지 마세요. 닫기 버튼·주요/보조 동작·선택 컨트롤·푸터·검색 결과·태그에도 연결해야 합니다. 주요 CTA는 포인트색 12%의 약한 tint를 유지하고, glass는 낮은 blur와 테두리 하이라이트를 함께 구현하세요. 태그 7px, 패널 14px, 검색 20px, 모바일 시트 22px 곡률 차이를 보존하세요.

모달은 공통 헤더/스크롤 본문/푸터로 구성하고, 검색은 Spotlight 배치를 유지하세요. portal로 렌더링되는 모달도 동일한 테마 변수와 재질을 받아야 합니다. Escape·포커스 이동/복귀·스크롤 잠금·처리 중 비활성·취소 제한은 원래 앱의 계약을 유지하세요. 카드의 주 동작을 보조 메뉴 열기로 바꾸지 마세요.

최종적으로 모바일/데스크톱의 대표 화면과 모달을 실제 렌더링으로 확인하고, 적용표에서 완료·해당 없음·남은 항목을 구분해 주세요. 디자인을 참고했다는 설명만으로 끝내지 말고 공통 표면이 일관되게 적용된 결과를 만들어 주세요.

---

## 짧게 요청할 때

> `ui-kit/ADOPT.md`를 기준으로 이 프로젝트의 전체 UI에 Web Reader 테마를 적용해 줘. `COVERAGE.md`에서 우리 프로젝트에 해당하는 화면을 매핑하고, 검색·설정·확인창·작은 진입 모달·메뉴·상태별 요소까지 빠짐없이 확인해 줘. 기능과 데이터 계약은 유지하고 디자인만 통일해 줘.
